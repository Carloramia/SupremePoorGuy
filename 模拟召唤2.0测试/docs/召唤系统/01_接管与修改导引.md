# 召唤系统 · 0.6试验接管

本文件只描述独立0.6试验副本，稳定0.5文档和代码保留在原工作目录。

入口仍为大地图书本、RitualPanel和原有喷涌。数据先提交，再播演出，再安置；结果不负责随机生成。

规则与配置：Scripts/Ritual/RuneRules.gd定义14符文、3奇物、stage与版本3布局；RuneBoard.gd只命中/绘制已解锁格；Scripts/SummonExperiment.gd集中试验门槛、基础数值、风险、结构分支、配方匹配和生成。

公共持久化：PrototypeState.gd保留原子保存与回滚。summon检查盘面、解锁、草稿、pending、余额和组合，记录last_summon。全部失败也提交消耗与失败记录，不能以false回滚一次已发生的失败；返回true只表示提交成功，实际成功只数见报告。

生成字段包括固定等段、基本数值、实际周期、部位耐久提案、能力、畸变来源、结构、队位、本体分身接口、批次、来源与时间。所有跨页操作只使用唯一ID。增殖不生成可持久化分身库存，战斗接口负责其未来入场。

GameDemo.gd绑定召唤UI、模拟解锁、测试构筑、风险确认、喷涌恢复和动态结果数。风险UI仅达到门槛后可见，保留固定区域避免阵面随提示变化；法阵左右滚动不影响中心。

同一次成功召唤最多5个真实实例；巨化3、超巨化1、定向1。部分失败不能补出缺失个体。结果卡继续通过State.move_monster/store_pending安置，缩小由State整组转移，不复制仓库规则。

所有试验数值、结构混用暂拒绝政策、演示配方和未实现范围见[本次指南](../05_召唤仓库调整与回退.md)。不要把演示配方当成已经定案的正式内容。

验收：ValidateNativeUI、ValidateUILayout、ValidateArtUI、ValidateSummonWarehouseV06、ValidateIsolation；CaptureExperimentV06生成8张实机图。覆盖方向识别、盘面边界、奇物扣费、风险阈值、每只判断、全部/部分失败、解锁与生成保存回滚、稳定实例和结果关闭入库。
