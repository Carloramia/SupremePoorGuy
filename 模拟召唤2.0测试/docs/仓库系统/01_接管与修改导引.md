# 仓库系统 · 0.6试验接管

本文件描述独立0.6副本，原0.5实现仍留在稳定工程。

WarehousePanel.tscn提供书页双栏；WarehouseEntry.tscn提供左页记录；MonsterDetail.tscn提供可复用右页详情。Scripts/UI/WarehouseBook.gd负责筛选、搜索、排序、选择与阅读状态，GameDemo.gd只绑定宿主通知和上层能力说明。

左页按仓库/出战/全部，以及等段/形态/畸变筛选。搜索按名称、关联按唯一ID；排序使用数值批次序号，避免batch_10排在batch_9之前。筛选无结果清除详情，操作与列表更新保留有效所选。

右页先显示名称、身份、固定核心属性，再显示概念形象、部位耐久提案、能力、畸变来源和召唤记录。它不重新抽属性，也不代表3D外观或已有战损；使用原有形态示意图时明确说明概念图。

改名和编队操作保持在右页固定区域，显示加入后的队位。State.occupied_slots/can_join/slots_after_join/transfer_ids统一管理占位：巨化2位、超巨化5位、同批缩小最多5只1位；试验总上限6位。缩小同批整组出入队，不跨批合并。

能力说明作为上层弹窗；返回恢复ID、筛选、排序、左右阅读位置与展开状态。不要在销毁的页面回调中创建新个体或推进剧情。

PrototypeState.gd持有唯一库存与存档，move_monster/rename_monster/store_pending保存失败恢复原状态。新增apply_battle_receipt只接受己方出战本体死亡编号；永久移除；胜利且可回收时按等段-1回收；分身数量不产生库存或回收；同一回执仅结算一次。真实战斗尚未接入。

本轮不进行存档迁移、交易、放生、经验成长、3D部位点选与真实外观。详细试验值与回退方法见[本次指南](../05_召唤仓库调整与回退.md)。

验收：新边界脚本检查空筛选、左选右显、搜索、改名、固定属性、队位不足、整组转移与回滚、说明返回、存档恢复、回执重复和死亡回收。六窗口尺寸持续验证左右滚动和操作可见。
