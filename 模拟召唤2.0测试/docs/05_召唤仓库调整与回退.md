# 召唤与妖兽仓库交互试验 0.6

2026-10-14 · 从原生UI交互原型0.5和提交0bacb93建立；已由用户试玩确认，整理到项目内独立目录“模拟召唤2.0测试”。内部交互版本仍为0.6。

## 运行

Godot 4.7.2普通版即可；本工程是GDScript，不需要C#或.NET。

导入本目录的 [project.godot](../project.godot)，确认名称为“涌现 · 模拟召唤2.0测试”，按F5。初次运行从300测试魔力与7格阵开始。

稳定版仍为仓库根目录的 `UI跳转原型/project.godot`。本轮不修改它、不覆盖主工程、不改网页原型。0.6不代表主工程已经接入。

## 试验参数，尚未定案

配置集中在 `Scripts/SummonExperiment.gd` 和 `Scripts/Ritual/RuneRules.gd`。界面提供“查看试验参数与配方”。

- 等段门槛试验为2/8/20/38格，且不超过法阵阶级；7格内只能生成一段。停用符文仍占格收费，但不计等段或畸变。
- 基准攻防血沿用策划案候选四段模板，生命和攻击随机±8%；攻击周期1.5秒。具体符文数值均为试算。
- 队位上限先用6；这不是新系统的正式容量定案。
- 风险源基础概率20%/35%/50%，每个超过门槛的重复+5%，上限90%；各源独立合成。普通分支每个体触发畸变后50%失败；成功按触发符文放大对应收益4倍，血刃代价暂不放大。
- 超巨化固定90%失败，成功生命×8、攻甲×5；其余重复源在成功后另行判断强化，不再额外增加失败率。
- 结构畸变单独试配：增殖本体×0.64、每本体2分身；缩小畸变尺寸更小、基础攻防血为普通缩小体的2倍。仍未经过实战平衡验证。
- 失败暂不返还消耗；部分失败只保留成功的实际个体，不补生成。
- 缩小同次召唤整组出入队，不足5只仍占1位，不跨批合并。结构符文混用暂阻止并提示“尚未定案”，避免暗自确定组合规则。
- 演示配方要求：甲片(-2,0)→(-1,0)，血脉(-1,1)→(0,1)→(1,1)，锐牙(0,-1)→(0,0)→(1,-1)，骨骰(1,0)(2,0)。不匹配额外笔画或奇物；通过测试构筑下拉框可直接载入。
- 奇物沿用原有形状、唯一性与说明；骨骰继续随机强化生命/攻击/移速10%。潮汐泵、棱镜心脏的触发行为仍没有真实战斗承载。

## 建议试玩顺序

1. 进入旅途，打开右下角召唤书。照血脉或甲片图形绘制、刻入，确认5只产出；逐只或全部入库。
2. 打开妖兽仓库，点击左页记录，在右页查看固定数值；测试改名、搜索、编队与撤回。能力说明返回后应保留同一编号和阅读位置。
3. 在召唤页左栏向下滚动到“试验控制”，模拟一次剧情解锁，载入“四甲片畸变”；确认前应看到风险，取消风险确认不扣费。
4. 分别载入巨化、增殖、缩小构筑；观察产出数量、队位和不可回收说明。缩小从任意成员操作都移动同批整组。
5. 解锁37格，再载入超巨化。它可能连续失败，这是90%试验失败率的正常结果；失败结果不生成占位妖兽。
6. 载入定向灵狼配方，核对骨骰与布局要求，确认只产出1只。保存法阵、关闭程序并重开，核对属性、编号和位置稳定。
