# Frontier Studio 地编工作台

面向地编的独立浏览器编辑器。代码、素材、工作集、Godot 转换器、测试和导出示例统一放在 `editor/` 中。依据本目录的《地图编辑器需求表.md》实现。现有工程唯一共享数据扩展是 `WorldMapDefinition.editor_data`，用于携带完整地编配置。

## 打开编辑器

直接双击 `editor/index.html`，用 Edge / Chrome 打开即可，无需安装 npm 包。推荐在项目根目录运行：

```powershell
./editor/tools/Run-Editor.ps1
```

需要 Node.js；启动后浏览器打开 `http://127.0.0.1:8765/editor/index.html`。服务器仅监听本机，提供静态文件，不提供磁盘写入接口。端口冲突可传 `-Port 8766`。页面不是 Godot 插件，不需要在 Godot 里开启插件。

初次打开载入示例工作集：连续探索地图和一个关联的六边形营地战场。浏览器刷新会重新载入示例，**编辑结果需要点击“保存工作集”保存到文件**。不要把浏览器缓存当作保存。

## 界面与日常操作

左侧选择地图、要素、素材和辅助图层；中间是画布，下方是对象列表和可点击定位的检查结果；右侧是当前对象或地图参数。

| 操作 | 方法 |
| --- | --- |
| 新增对象 | 点击左侧要素，再点击画布；也可拖放要素卡片 |
| 选择 / 定位 | 点击对象；对象列表单击选中，双击居中 |
| 移动 | 拖动选中对象；开启吸附后按世界单位步长定位 |
| 精确调整 | 右侧输入位置、旋转、缩放、视觉尺寸；修改后离开输入框或点击“应用参数” |
| 复制 / 删除 | 右侧按钮，或 Ctrl+D / Delete；复制自动分配新的唯一 ID |
| 平移 / 缩放 | 中键拖动或空格+拖动；滚轮以鼠标为中心缩放；“适配画布”恢复总览 |
| 撤销 / 重做 | Ctrl+Z / Ctrl+Shift+Z；支持放置、拖动、参数、节点、删除、地图尺寸和引用表修改 |
| 保存 | Ctrl+S 或“保存工作集”；支持的浏览器可选择保存位置，其余浏览器下载文件 |
| 图层 | 独立开关衬布、装饰、视觉、道路、碰撞、效果、初始揭示区等；只影响编辑显示 |

输入框正在编辑时，Ctrl+Z 遵循文本编辑行为；离开输入框后撤销地图操作。预览模式禁止修改布局，先切回“布局编辑”。

## 编辑探索大地图

1. “地图设置”调整连续地图范围、出生位置、地面、背景、后台 Hex 元数据。可选自定义外轮廓是地图坐标多边形；留空为矩形。画布不显示整套 Hex 格线，不把地图裁切成一个六边形。
2. 放置道路。中心线节点使用对象局部坐标；节点列表可增删、调序。“画布编辑”拖动青色节点，“画布加点”连续点击追加，Esc 结束，选中节点后 Delete 删除。宽度、样式、连接 ID、层级、现有移动倍率及吸附距离独立配置。
3. 放置小屋、城镇、营地，设置稳定 ID、视觉和点击区域。点击区域的形状、偏移、旋转和尺寸独立于图片。目标场景填 `res://...tscn`；事件使用引用 ID。
4. 可破坏障碍设置碰撞、破坏条件、破损素材、被阻挡的地点或连接 ID。示例 `has_monster` 条件要求至少一只怪兽；`camp_barrier_01` 仅关联 `monster_camp_01`。
5. 可跨越障碍必须设置条件引用和落点，跨越不销毁障碍。不可破坏障碍没有破坏选项，也不能导出破坏奖励。
6. 营地设置战斗地图 ID、敌方配置、己方部署区域、战后事件、关联障碍，以及焦点放大的转场参数。推荐先建战场和部署区，再绑定营地。
7. 装饰和树木不自动生成碰撞；需要阻挡时关联单独配置的碰撞对象。衬布是独立底层，不拦截点击、不参与寻路、不影响世界轮廓。

所有 ID 建议使用英文字母、数字、下划线、点或横线。对象 ID 在整个工作集唯一；修改 ID 会更新内部地标阻挡、战场、部署区和碰撞关联。外部游戏系统中的字符串 ID 仍需同步维护。

## 迷雾、发现和存档预览

地图参数包含启用开关、揭示来源、实际世界单位半径、未知/已探索颜色和透明度、纹理、羽化及渐变。`permanent` 永久揭示；`recover` 离开当前视野后用已探索颜色重新覆盖。

“初始揭示区域”可以放置多个，支持矩形、圆形和多边形。地标另外配置初始标记可见、发现条件、发现距离、迷雾上方/下方显示和隐藏时能否交互。**区域已揭示与地点已发现是两份状态**。迷雾透明度为零仍保持未知逻辑；关闭迷雾不会把隐藏地点自动记为已发现。

切到“迷雾模拟”，点击空地移动模拟玩家，沿移动路径记录探索。缩放、平移和查看地图不会产生探索。“临时全揭示”只改变显示；“重置预览”清除临时探索、发现、破障和奖励领取状态。怪兽数量和外部条件开关用于验证门槛。探索模式点击障碍可验证条件和局部解锁；营地解锁后点击可查看焦点转场并进入关联战场预览。

“读取游戏存档”支持当前工程的版本 1 大地图 JSON 存档：地图 ID 必须匹配，读取玩家位置、胶囊探索记录和地点发现状态。该操作只读，不修改源存档，不把玩家进度写入工作集，也不承诺恢复未由当前存档格式记录的破障状态。

## 编辑六边形战场

左上选择战斗地图，或使用“＋”新增。编辑器俯视摆放；平面坐标是 Godot X/Z，另有离地高度 Y。改变半径或朝向只重算地面、自然边缘和六面空气墙，已有对象坐标保持不变；越界对象在检查结果中定位。

| 类型 | 重点配置 |
| --- | --- |
| 碰撞伤害障碍 | 视觉与碰撞独立；形状、体积高度、物理层、伤害、触发间隔、作用对象 |
| 落穴 | 区域、深度、效果引用、作用对象；深度是玩法数据，不在预览中挖真实地形洞 |
| 荆棘 / 泥潭 | 效果区、高度/深度、减速比例、离开持续时间、作用对象；不会自动成为实体石墙 |
| 蛛网 | 捕获区、最低/最高高度、控制效果、时长、间隔、作用对象，默认 flying |
| 草 / 树 / 自然贴片 / 路障残骸 | 独立视觉与显示层级，不推导碰撞 |
| 空气墙 | 地图级厚度、高度、碰撞层，跟随六边形，预览不可见 |
| 己方部署 | 独立区域、朝向、局部槽位及规则引用；检查场外、区外、槽位重叠、障碍与坑洞 |
| 敌方怪兽 | 每个对象独立的配置 ID、位置、朝向、分组，数量不限定三只 |
| 战后中心点 | 解锁条件、事件 ID、召唤/升级选项、点击范围和防重复领取策略 |

“场景预览”隐藏编辑辅助线。战场保持整张清晰；六边形外独立背景虚化，边缘羽化，单位不参与背景模糊。“模拟胜利”开启临时胜利条件，点击中心祭坛检查召唤/升级事件引用，领取只发生在本次模拟。

## 素材和业务引用

内置 16 个 SVG 占位素材，可用“导入图片素材”添加 PNG/JPG/WebP/SVG。图片嵌入工作集，单张限制 8 MB，Godot 转换时生成为资源。选择对象后点击“素材库”中的图片可替换视觉；没有选中对象时会放置装饰。

条件、事件、效果、怪兽、敌方队伍、部署规则和事件选项统一通过“条件 / 事件引用表”维护 JSON 列表，每项使用稳定 `id` 和可读 `name`。编辑器只校验关联和模拟条件；不要把运行中怪兽实例写到这里。未接入的外部条件用模拟开关测试。高级配置 JSON 用于保留扩展字段和项目资源引用，应用前检查结构。

## 保存、导出与回到 Godot

“保存工作集”生成 `*.mapproject.json`，允许保留尚未完成的配置。“导出配置”生成相同结构的 `*.level.json`，有错误时阻止导出。两种文件均可通过“打开”重开，包含地图、素材和引用表，不包含预览状态。每次交付应保留工作集作为源文件。

在项目根目录执行（把 Source 改为实际下载文件）：

```powershell
./editor/tools/Import-Level.ps1 -Source ./editor/examples/Frontier.mapproject.json
```

先检查配置和 Godot 资源路径，再在 `editor/exports/` 生成：

- `initial_configuration.json`：完整初始配置，供玩法系统读取。
- `frontier/WorldDefinition.tres` 与 `frontier.tscn`：现有大地图数据资源和可运行场景。
- `camp_battle_01/SceneDefinition.tres` 与 `camp_battle_01.tscn`：现有 2.5D 框架资源、真实空气墙、显式碰撞和效果区的预览场景。

Godot 打开项目，双击导出的 `.tscn`，F6 运行；不要双击 `.godot` 缓存文件。转换器从 `-GodotPath`、`GODOT_BIN`、本地 `.tools/godot` 或 PATH 查找 Godot，引擎不随 GitHub 包分发；`-Output res://editor/exports/版本名` 可隔离版本。输出限制在 `editor/`，同名输出会更新，源示例场景不被覆盖。

导出的探索场景沿用当前 WorldMapController：道路中心线、加速和吸附、静态障碍、地点、城镇 2.5D 悬浮入口可由现有系统运行。**新增的完整迷雾规则、破障/跨越条件和营地战斗流程由 `initial_configuration.json` / `editor_data` 交给游戏程序接入；浏览器中的验证模拟不会自动成为原有大地图玩法。** 战场输出创建几何、物理区域与元数据，真实伤害、减速、蛛网控制、自动布阵、战斗结算与召唤升级由玩法系统处理。

## 导入现有大地图

```powershell
./editor/tools/Import-WorldMap.ps1
```

默认读取现有 `world_map/demo/WorldMapDemo.tscn`，输出 `editor/examples/FrontierImported.mapproject.json`。用编辑器“打开”载入。保留地点 ID、原始地点资源、道路点、禁用 Hex、出生点和自定义速度区；附带示例战场供后续绑定。原生营地尚无本编辑器战斗绑定时会提示补全，不擅自分配战场。可用 `-Source`、`-Output` 指定其他文件。

## 检查和交付

先点“检查配置”，点击结果定位对象。错误包括重复 ID、缺失引用、非法数值、道路退化、多边形自交、越界及非法部署位置。浏览器可验证声明的引用；实际 `res://` 文件存在性在 Godot 转换时验证。

```powershell
node ./editor/tools/Validate-Level.cjs ./editor/examples/Frontier.mapproject.json
./editor/tools/Run-Tests.ps1 -Render
```

当前自动验证覆盖 33 项共享模型逻辑和 14 项 Godot 导出检查；渲染模式额外实际运行战场并保存截图。浏览器已实测参数应用、失焦提交、撤销重做、放置复制删除、战场缩放越界提示、预览胜利/重置、迷雾全揭示及浏览器错误日志。详细数据接口见 [接入说明](docs/DATA_CONTRACT.md)。
