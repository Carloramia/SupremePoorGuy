# 召唤系统 · 接管与修改导引

2026-10-11 · 对应运行版本0.5 · 实现事实与后续建议分开记录。

## 1. 职责与当前能力

大地图书本直接打开原生召唤界面。61格法阵支持相邻笔画、识别刻入、启停、删除、撤回、取消、奇物点放／拖放、保存和清空确认。成功召唤暂定产出3只测试怪物，先保存，再切到当地场景播放喷涌，最后安置。

环境、天气、引导物的完整生成权重与真实战斗效果未实现，不可把描述文本当成已有能力。疾风与双峰的原生纠错已经用户批准，网页未修改，详见 [差异说明](../03_网页规则移植与差异.md)。

## 3. 现有调用与交界

当前实际方法，不是新拟接口：

- `GameDemo._open_ritual / _build_ritual / _refresh_ritual`：打开与刷新。
- `_commit_rune / _undo_rune / _cancel_rune`：操作草稿。
- `_summon / _resume_pending / _eruption_done / _results`：确认、恢复、演出结束与结果页。
- `_book / _trait`：当前符文辞典及特性说明仍在公共控制器中。
- `RuneRules.export_layout / import_layout`：输入输出版本2的 `placed / placedRelics`。草稿不随普通布局保存。
- `PrototypeState.save_layout / summon`：保存布局与一次性召唤事务。
- `scene_requested("summon", location_id)`：现有对外通知，通知时生成与保存已成功，不应由宿主再次扣费或生成。

成功顺序：校验 → 一次扣费与生成 → 写入实例和pending → 保存成功 → 请求喷涌 → 显示同一批结果。保存失败回滚，不播放成功演出。存在pending时禁止再次生成，先恢复上次安置。

召唤结果页展示的是已经存在的实例。`_monster_card`及`PrototypeState.move_monster / store_pending`是交界：调用它们进行安置，但不要在本系统重新实现队列上限和库存转移。

## 4. 数据契约

- 生成写入怪物 `id/name/form/hp/attack/armor/speed/traits/position/color`，另保留 `source_location/source_layout`。
- `id` 是跨系统唯一身份；`name` 可改，不能用于关联。当前ID随召唤serial生成，正式接入时仍须唯一。
- 新生成的 `position="pending"`；安置只把同一实例转为 `warehouse/team`。
- `pending_location/pending_return`用于退出后恢复；演出不得重新抽取属性。
- 当前一批3只、逐格测试魔力、全部符文开放均为验证参数，不是正式策划定案。

存档只有公共一份。未来拆分生成服务时，由集成人员定义统一提交与回滚；不能先扣费，再调用可能失败的独立库存写入而没有恢复机制。

## 5. 按任务修改

- 改图形、占格或奇物：先改RuneRules，核对旋转／镜像／反向及相邻，再改符文书视觉。禁止只换小图、不改识别定义。
- 改召唤UI：编辑RitualPanel与组件场景。维持阵面正方形、左右滚动，不在控制器里写尺寸或把美术背景烘焙成按钮文字。
- 改产出：当前入口是PrototypeState.summon，需要协调公共文件；保留唯一实例、保存失败回退、pending恢复，不改仓库统计和位置规则。
- 改喷涌：只替换演出部分，保留eruption_finished通知。后续可独立成动画场景，但当前尚未这样拆分。

当前采用用户素材参考的纸雕分件主题，沿用公共画板动效，见 [美术指导与素材格式](../美术方案/03_纸雕UI_美术指导与素材格式.md)。底纸、叠层框、夹子和按钮底各自独立；不复制共享Theme或BoardMotion。B幕布未实现。正式工程接入先看 [团队接入速读](../00_团队接入速读.md)。

## 6. 接管验收

运行现有 `Tests/ValidateNativeUI.gd` 与 `ValidateUILayout.gd`，修改共用卡片时也回归仓库。

必须检查：7符文全部方向；停用仍占格；奇物冲突与唯一性；草稿未处理阻止召唤；余额不足不扣费；一次产出3只；保存失败完整回退；喷涌中退出能恢复相同产出；结果直接关闭剩余入库；长列表／提示不挤动阵面。

提交时附修改文件清单、测试结果、图案或布局版本变化，更新本导引。需要编辑GameDemo、PrototypeState、WorldView或共享Theme时先协调集成人员。不得重写另一系统的同名规则来绕过共享依赖。
