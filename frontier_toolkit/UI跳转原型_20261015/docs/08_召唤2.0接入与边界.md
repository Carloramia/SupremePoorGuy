# 召唤2.0功能接入记录

2026-10-15 · UI跳转原型0.7.9 · 来源：仓库内“模拟召唤2.0测试”（内部交互版本0.6）。

本次只回收召唤规则、盘面输入、确认、结果及必要的安置数据兼容。保留当前C1/C2/C3独立纸页、铜环、原生手写字体、TA换肤插槽、书页进退动效和窗口适配。没有覆盖试验工程的GameDemo、主题或project.godot；没有引入其WarehouseBook或战斗回执。其他系统接口仍以原联调协议为准，涉及召唤的旧“三只/七符文/61格固定盘面”说明由本记录替代。

## 功能差异与当前入口

| 功能 | 原跳转原型 | 接入后 |
|---|---|---|
| 盘面 | 固定61格 | 7→19→37→61格，状态保存；试验解锁不扣魔力 |
| 符文 | 旧7枚 | 2.0的14枚，支持连续绘制、旋转、镜像、反向识别、启停与删除 |
| 费用 | 只计符文 | 符文和奇物按占格同价，停用仍收费但不计等段/重复风险 |
| 生成 | 固定3只，占位随机属性 | 普通5只，等段由有效投入及阵阶确定；数值来自2.0配置 |
| 结构 | 无 | 巨化3只/每只2队位；超巨化尝试1只/5队位；增殖附分身数据；缩小5个体同批整组/1队位 |
| 畸变 | 无 | 基础4枚、强化3枚、最强2枚起风险，确认前不扣费，按个体产生普通/畸变/失败 |
| 定向 | 无 | 精确空间配方加骨骰生成1只铁甲灵狼；支持配方整体平移、旋转、镜像 |
| 结果 | 3张卡 | 报告尝试/成功/失败/实际扣费，卡片自动换行，列表需要时内部滚动，全部入库固定 |

C1保留环境、魔力、消耗、等段/数量/队位、已刻入列表，增加风险及试验解锁/构筑/配方入口。C2保留阵面和固定操作，C3保留符文与奇物折叠页。14枚符文及增长后的列表允许必要的内部滚动，不压缩文字来强塞首屏。结果详情额外显示攻击周期、结构、队位、畸变来源、分身与部位耐久；仓库详情布局保持原版。

## 文件与接口

- Scripts/Ritual/RuneRules.gd：回收2.0规则，layout版本3，字段stage/placed/placedRelics；LEGACY_RUNES只支持原辞典与历史妖兽特性说明，不参与新召唤。
- Scripts/Ritual/RuneBoard.gd：按stage绘制和命中检测，锁定格不能点击，沿用原美术插槽及输入组件。
- Scripts/SummonExperiment.gd：2.0生成算法与试验参数。preview(rules)返回cost/effective_cost/tier/mode/count/slots_each/total_slots/sources/mutation_chance/failure_chance/error；generate返回units及report。
- Scripts/PrototypeState.gd：summon(rules,location,return_route,test_rng=null)，生成前校验盘面/已解锁阶级/草稿/有效符文/消耗，整笔保存成功才演出。全失败也完成交易并保存报告，不返费、不补怪。
- unlock_next_stage(layout)：模拟剧情解锁替身，不是真实剧情接入；occupied_slots/can_join/transfer_ids仅用于兼容新生成物。普通和旧怪仍1只1位，巨化/缩小按2.0口径安置；缩小不可回收。未引入新仓库搜索、排序、筛选、详情布局或战损结算。
- GameDemo：只绑定召唤页和结果流程；结果按钮继续调用原有入库/编队接口。队位校验共用同一模型，避免结果入队与之后仓库移动出现两套规则。A2、地图、事件、待办、战斗奖励与其交互保持当前行为。

scene_requested和party_changed仍为通知信号，并未变成异步正式生成/战斗服务。真实战斗中护盾、灼烧、回血、分身及部位破坏依然没有接入。等段门槛、概率、倍率、结构组合阻止规则与配方均沿用2.0试验参数，不在此次重新平衡。
