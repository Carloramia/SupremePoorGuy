# 仓库系统 · 接管与修改导引

当前接入基线0.7.6：[系统接入适配与联调协议](../07_系统接入适配与联调协议.md)及[组件接口](../06_组件隔离与TA材质接口.md)优先；下文旧版导引保留具体文件与规则背景，交互入口以当前协议为准。

2026-10-11 · 对应运行版本0.5 · 不把召唤系统纳入仓库内部。

## 1. 职责与当前能力

可从顶栏直接打开仓库或出战队列，按仓库／出战／全部筛选，查看形态、属性、特性与来源，查看详情、改名，进行出战／入库转移。出战上限当前6只，未接入负伤、死亡、交易、解契或永久删怪。

召唤产出3只的规则属于召唤，仓库只管理给定实例。详情与特性说明不推进游戏、不重抽属性，也不因为未进入召唤页而不可用。

## 3. 当前实际接口

- `GameDemo._warehouse(filter)`：当前筛选参数是 `warehouse/team/""`，空字符串表示全部。
- `_detail(id)`：按唯一实例编号打开详情与改名。
- `_monster_card(parent, monster, result_card)`：共用卡片填入和操作，结果页也调用。
- `_refresh_sidebar / _update_header`：更新宿主摘要。
- `_term / _trait`：共享说明入口；当前特性描述仍从符文定义查询，未来应改为公共能力词典，而不是在仓库复制召唤规则。
- `PrototypeState.monsters / monster_by_id`：当前读取返回实际实例引用，非只读快照；UI不应直接修改其字段，变更应调用正式写入方法。
- `move_monster(id, position)`：只接收 `warehouse/team`，负责上限、pending移除、保存和失败回退。
- `rename_monster(id, new_name)`：去首尾空白、最多24字符、空名拒绝，保存失败回退。
- `store_pending()`：把所有剩余pending实例入库，清pending，保存失败回退。
- `party_changed(monster_ids)`：当前由卡片转移成功后的控制器发出；直接调用State方法不会自动发信号，接入方必须统一处理成功通知。

## 4. 与召唤的交付边界

实例只有 `pending/warehouse/team` 三种位置之一。召唤事务负责创建并保存pending实例；结果页将这些同一实例交给位置转移方法。

- 仓库不调用随机生成补出卡片，不根据中文名称重新创建实例。
- 队列满时，加入失败但仍可入库；不能把失败显示成成功或丢失怪物。
- 关闭结果页时剩余入库；若保存失败，阻止成功关闭，继续提示错误。
- 查看详情和术语关闭不应误调用结果批量入库。
- 修改怪物卡的公共结构时，要一起检查继承的结果卡和两边的数据绑定。

数据字段由公共PrototypeState持有。未来正式仓库承接实例时，需要集成人员与召唤负责人约定统一提交、恢复及唯一ID；目前不存在可跨工程直接调用的 `receive_summon_batch` 服务，不能把建议名称当成已实现API。

## 5. 修改路线与美术接入

- 改列表／详情布局：编辑WarehousePanel和MonsterDetail，不在控制器新建一整套UI。
- 改卡片与画框：编辑MonsterCard及继承结果卡；正文与数值必须保持为独立文本节点。
- 换怪物图：编辑Portrait/Artwork插槽；正式每实例素材应由资产ID绑定，不能以改名字选择图片。当前UI未接入完整资产注册表。
- 改队列容量／改名限制：当前涉及PrototypeState的公共规则与详情输入上限，以及顶栏显示，不可只改某个UI标签。需要协调整合，回归召唤结果安置。
- 加画板移开／卡片滑入：使用独立视觉动画，不改变实例位置作为动画中间态；位置变化以业务成功回执为准。

当前采用用户素材参考的纸雕分件主题，沿用公共画板动效，见 [美术指导与素材格式](../美术方案/03_纸雕UI_美术指导与素材格式.md)。底纸、叠层框、夹子和按钮底各自独立；不复制共享Theme或BoardMotion。B幕布未实现。正式工程接入先看 [团队接入速读](../00_团队接入速读.md)。

## 6. 接管验收

运行 `Tests/ValidateNativeUI.gd`；改布局或共享卡片还需 `ValidateUILayout.gd` 及关键截图检查。

必须检查：空仓库；三种筛选；唯一ID不变；加入、撤回与第7只失败；改名保存与重启；多层详情／特性返回；多次出入不复制实例；pending安置及关闭结果入库；保存失败回退；不读取正式工程存档。

当前不存在两个独立库存文件；不得为了“系统独立”各自保存同一怪物的拷贝。接管后在本导引记录修改入口、共享文件变化、测试结果和迁移限制。
