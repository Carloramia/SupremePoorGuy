# 网页规则移植与差异

2026-10-11 · 网页仅只读参考，本次没有修改 `模拟召唤`。

## 移植对应

| 网页逻辑 | Godot 实现 |
|---|---|
| hex-grid.js：61格、轴坐标、距离、变换 | RuneRules.gd：cells / distance / transformed |
| rune-engine.js：草稿、识别、刻入、占格 | RuneRules.gd：extend / recognize / commit / owner_at |
| 启停、删除、奇物唯一性和布局 | RuneRules.gd：placed / remove / preview_relic / import_layout |
| app.js / SVG交互 | RuneBoard.gd 与 GameDemo.gd 的原生 Control 输入 |
| browser localStorage | PrototypeState.gd 独立 user 目录内 JSON |

保留：平移、六向旋转、镜像、反向笔顺识别；同笔不重复格；连续相邻；停用仍占格；奇物不与符文共格；同种奇物单阵唯一；布局 version 2 字段 `placed` / `placedRelics`。导入时额外校验合法整数坐标、重复格、图形匹配，拒绝明显损坏条目。

## 用户批准的纠错

### 疾风：消除与回潮同形

网页旧图：`[[0,0],[1,0],[2,-1],[2,-2],[1,-2]]`

Godot新图：`[[0,0],[1,0],[2,0],[2,-1],[3,-1]]`

旧图在允许镜像／旋转时与回潮相同。网页按定义顺序匹配，结果为回潮。新图保持5格，且所有12种方向及反向笔顺均不与其他符文冲突。

### 双峰：修正非相邻笔画

网页旧图：`[[-2,1],[-3,0],[-2,-1],[-1,-1],[-1,0],[0,1],[1,1],[2,0],[2,-1]]`

Godot新图：`[[-2,1],[-3,1],[-2,0],[-1,0],[-1,1],[0,1],[1,1],[2,0],[2,-1]]`

旧图包含距离2的移动，无法按相邻规则正常绘制。新图保持9格，每段相邻，所有变换均唯一。

旧网页布局中的这两枚符文若按原图导入会被严格校验忽略，不能声称旧布局完全无损兼容。本轮不提供跨浏览器存档自动迁移。

## 其他明确差异

- Godot的“连续笔触吸附”是拖动期间采样补格，不是网页的自由笔触松手后重建算法。正常精确蜂窝输入已移植；不会宣称自由手绘视觉完全一致。
- 当前法阵内关闭保留内存草稿；重启只恢复明确保存或成功召唤时保存的布局，不保存未刻入草稿。
- 网页描述的战斗效果并没有真实战斗后端。本原型保留说明与产出标签，不伪装已经实现治疗、贯穿、护盾或邻接战斗增益。
- 新增3只产出、仓库／队列、喷涌与测试经济是本轮确认范围，不是网页已有能力。
