# 事件内容与接入规范

版本：v0.8 · 2026-10-19 · 状态：规则确认与接入约定，待正式宿主绑定。

2026-10-19当前策划范围：9类符文、8件奇物。缩小效果并入大群，不再单列tiny／缩小；轻步、溅击、缓行暂不接入。螺旋人像普遍增加肢体，不提高变异率；结晶化眼球每次用于召唤保证1只获得可发射射线的魔眼，不再是概率提高。肢体数量与适配、魔眼个体选择和射线参数待定。实际程序ID、图形、属性和旧存档迁移需另行接入，本轮仍只改文档与配表草稿。

## 2. 接入范围与真实能力

本次仅整理内容和接口约定，不接入游戏、不改原型布局、不修改奖励或战斗实现、不写玩家存档。后续遵守[交接约束](../交接文档.md)：默认改功能不改布局；需要移动控件、改变字号或有布局挤压风险时，先准备具体方案并取得用户二次确认。

当前需要区分三种格式：

1. **写作/项目草稿**：`schema_version=1`，根字段为`name / tables / stories / flows / flow_notes / flow_layouts`。本批交付属于此类。`tables`沿用工具七张业务表，`stories`保存段落，`flow_notes`保存不执行的接入说明。20条正文和3条辅助记录均为`草稿`，没有伪造正式入口ID。
2. **旧七表业务配置**：事件、阶段目标、剧情节点、选项、条件、结果、地图绑定。正式宿主需要实现加载、条件求值、事务和状态推进。工具能导出不等于游戏能执行。
3. **Godot单事件展示格式**：工具README描述为`schema_version / id / title / start / reward_mode / nodes`。不能把本批`.events.json`改个后缀就当成`.event.json`。对白/选择/奖励/结束四类展示节点也不能替代战斗等待、献祭、交易与跨地图任务执行。

前次整理核对发现：现有配表工具有`schema.js / model.js / story.js`，README提到的`flow.js`及Godot事件工程`core`运行文件在当前工作区缺失。这里只校验现存数据模块的导入与字段，不宣称网页全流程、Godot事件演示或正式主工程运行通过。UI原型的事件面板仍是展示组件，不是通用事件执行器。历史能力说明见[系统接入适配协议](../docs/07_系统接入适配与联调协议.md)。

导入前先在工具中保存现有完整项目。工具的“导入”会替换当前浏览器工作区；本次没有自动导入、覆盖浏览器草稿或改动工具种子数据。导入后从情节写作入口检查原稿，依据总表绑定执行分支；正文中的【选项】不会自动成为可执行选项。

## 3. ID与字段约定

已有明确映射时沿用工具ID：火速任命`QST_MAIN_001_001`、图书馆开门日`QST_SIDE_001_001`、防卫预算`QST_SIDE_002_001`、血祭日`QST_SIDE_003_001`。其余本批分配`QST_GRASS_序号`，三个辅助入口使用`AUX_GRASS_名称`。不能用事件显示名替换正式ID；若宿主已有ID，增加映射，不覆盖旧进度。

| 字段 | 含义 | 必须避免 |
| --- | --- | --- |
| event_id | 稳定的内容与存档关联ID | 改文案标题就换ID；与地图ID混用 |
| region_id / cell_id / location_id | 地区、格子、地点的正式标识 | 只填“草原”就宣称已绑定位置 |
| interaction_id | NPC、货车、祭坛等实际入口 | 将正文中的NPC称呼当作正式资源ID |
| 开放/触发条件 | 谁、何时、在哪种状态可进入 | 空条件或待定解释为自动通过 |
| stage_id | 同一事件内阶段，例如等待回城 | 把每个阶段算作一个新事件 |
| branch_key | 选项稳定键，总表第一列 | 用按钮排序或完整中文台词当存档键 |
| 展示正文 | 旁白、说话人、笔记与选项标签 | 把括号里的奖励/判定注释当对白 |
| battle_map_id / enemy_config_id | 战斗场景与真实敌方预设 | 缺预设时替换敌人、传空敌军自动胜利 |
| reward/item/rune/preset ID | 真实资源标识 | “奇物”“符文”当作任意默认奖励 |
| once_key / request_id | 奖励去重键与操作请求关联键 | 每次重开面板生成新领奖键 |
| publish_status | 草稿→待绑定→联调→可发布 | 待定字段尚未补齐就标可发布 |

总表的`active / complete / battle_pending`等状态词和分支键是策划约定，并非新注册的宿主字段或已实现API。正式字段需要系统负责人映射。读取怪物的攻击力、体型、皮毛、飞行与手足组件都用正式数据，不从立绘、中文名字或显示尺寸推断。

## 4. 节点、分支与外部等待

每个执行节点应有稳定`node_id`、类型、正文/说话人、下一节点；选项另有分支键、可见条件、可选条件、不可选提示与去向。正文、选项、条件、动作必须分离。节点读完或窗口关闭只结束播放，不能自动完成事件。07号的归还明确由指定共用对话完成，不等待实际护送；18号只有当前阶段奖励成功，才开放下一阶段。

- **纯对话**：按正文顺序展示，确认结束；有奖励时等待提交成功再完成。没有写明玩家选择的台词不扩展成分支。
- **战斗**：玩家选择/已确认遭遇→按模式校验阵容（玩家战斗校验玩家队伍与敌军；观战只校验两方AI阵容）→保存本次请求→进入战斗→等待对应结果→胜利后展示后文、结算。失败、加载失败、取消和退出均不进入胜利路线。
- **跨地点任务**：接取→持久保存阶段→离开窗口→在目标城市/入口按阶段路由→交付。不得把“以后帮你问”立即接到领奖节点。
- **能力判定**：确认时重读正式持有怪物字段；10号包括仓库和出战怪物，任意单只攻击力高于阈值即可，不要求先入队。失败保留未完成，不凭全队加总代替单只攻击力。
- **互斥路线**：富含矿物质、谁会赢？在成功终局后锁定，其他终局不可再次领取。过分敬业更早在接取回城路线时锁定，之后不能改选直接解决，离开或读档不解除锁定。
- **汇合奖励**：外行魔法师的两种回答共享同一奖励节点，不能两份各发一次。
- **离开**：没有额外说明时不扣费、不领奖、不完成、不抹除已发现/已接取阶段。一次性与完成后隐藏是本次默认接入建议，原稿未定的重复规则仍可由作者调整；不要在未确认前将其作为正式发布规则。

同一事件有互斥选择时，选择确认与执行必须再次读取最新状态。连点、两个窗口或读档后重试不能同时完成两条路线。

## 5. 事务、奖励与持久化

展示组件只发出意图，正式宿主拥有魔力、怪物、天气、事件进度和存档。不得让原型与正式服务各扣一次、各保存一份。推荐的语义事务为：校验→生成/复用请求→锁定结果→提交消耗、奖励、状态及去重账本→成功回执→刷新UI。具体实现由宿主决定，不在文案中绑定函数名。

一次性结果键可按`event_id:stage_id:result_id`映射到宿主账本；重复事件按持久`round_id`或`encounter_id`区分。操作重试复用原请求，不重新随机奖励或重复消耗。

- 购买引擎：扣100魔力、扩一圈、购买标记属于同次事务；余额不足、满级、保存失败不得只完成一半。
- 献祭：选择实际怪物实例→显示将消耗的对象→不可逆确认→复核实例可用及条件→回收、奖励及阶段进度按同一请求持久提交。下一要求必须等本阶段奖励成功后才显示；若已消费待发奖，重试不得再次扣怪。天气效果未定，不擅自写入默认天气。取消不回收。不能因为一个怪物满足多个标签就重复消费同一实例。
- 怪物奖励：谁会赢？的强化双头甲狼/魔眼拱兽必须有实际预设和实例ID；库存或队伍容量不足时按正式安置规则处理，不能静默丢弃或直接插入满员出战队伍。
- 结果回执：至少关联事件、阶段、分支、请求及战斗ID。旧战斗或重复回执不能推进当前另一分支。
- 随机行为：需要明确概率、候选池、抽取时机与持久结果；打开窗口、查看文本、读档重试不能擅自重掷。

## 6. 显示与完成规则

待办只显示当前尚未完成且可行动的目标；完成记录不继续占用待办列表。一次性事件成功提交且无后续时隐藏对应事件图标。城市、图书馆等共享入口继续保留；只移除其中已完成的任务选项。

“已发现”“已阅读”“已接取”“战斗胜利”“已领取”“已完成”是不同状态。离开不等于失败，更不等于完成。有后续时切换到正确阶段入口；不可直接删除整条事件链。

战斗结束顺序遵守现有原型：先弹结算，玩家结束结算后再由整个大地图下拉遮挡小地图。事件正文继续使用现有纸质面板、安全标题留白、固定选项与原有字体，不为接入内容修改布局。战斗地点的简短概况沿用悬停显示，点击才执行确认后的入口逻辑。

大地守卫Boss战后发苔藓心脏1件，来源已确定；实际Boss预设、入口、胜利回执与奇物ID待绑定。不把05听闻事件或其他Boss自动作为该奖励来源，也不增加本批20条事件的虚构记录。

## 8. 从草稿到发布

1. 对照总表确认文案与分支，补齐每条“尚需绑定/确认”；保留当前文件之外的候选灵感，不混入正式20条。
2. 绑定正式地图入口、怪物/物品/符文/天气字段与宿主服务；沿用已有任务ID或登记映射。
3. 从写作稿手工编排执行节点。正文里的奖励说明留在配置备注，不能直接展示后视为已发奖。
4. 逐条绑定：事件总览→阶段目标→剧情节点/选项→条件→结果→地图入口；若采用另一正式运行时，提供同义映射表，不要求照搬旧七表。
5. 补全演示/宿主缺失模块后再验证真实节点执行；使用预览只能证明文本分支，不能证明战斗、交易或存档事务。
6. 按以下验收项在隔离存档完成联调，经过内容负责人确认再标记可发布。

## 9. 最低验收清单

- 每条已发布事件有真实入口和唯一ID，无断链、无不可达终局、无“待定”执行参数。
- 初次进入、提前关闭、重新进入、读档后继续均路由正确；城市访问先后不被错误锁定。
- 年迈的驴子分别按驴→商人、商人→驴测试，共用一段归还对话，不依赖实际护送；两件奇物只发一次。
- 过分敬业接取回城路线后立即禁止直接解决，重进和读档不解锁；富含矿物质两路完成结果互斥，不能重复领奖。
- 甲壳圣堂验证单只攻击力不足、等于、高于阈值；仓库中合格而出战不合格时仍通过，不要求临时入队，也不使用总攻击力蒙混通过。
- 废弃矿井验证大型队伍、混合队伍、空队伍、合格队伍；不合格时不删怪，不以空队伍入场。
- 所有战斗验证胜利、失败、退出、加载失败、重复与过期回执；未胜利不发胜利奖励。
