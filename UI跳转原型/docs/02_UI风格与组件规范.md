# UI 风格与组件规范

版本 0.3 · 2026-10-11 · 对应 `Assets/UI/PrototypeTheme.tres` 与 `Scenes/UI`

## 设计目标

把纸偶战斗单位、法阵绘制与妖兽管理放进同一套清楚的界面语言。以纸张底色承载正文，以深墨色保证读数，以铜色边框表现结构和层级。参考截图中的卡片与说明窗逻辑，不直接使用其红黄配色，不通过装饰遮挡属性或主操作。

## 唯一视觉参数入口

| 参数 | 当前值 | 用途 |
|---|---|---|
| INK | #263B3B | 主要文字、轮廓和全局背景 |
| PAPER | #EEE2C8 | 窗口、卡片和正文底色 |
| TEAL | #376F68 | 可交互按钮、己方标识 |
| GOLD | #BC8942 | 铜钉、边框与焦点 |
| RED | #A45243 | 敌方占位、危险语义 |
| MUTED | #67766A | 次要状态与禁用边框 |

字体：优先 Microsoft YaHei，回退 Noto Sans CJK SC / sans-serif。正文18，说明16，卡片标题24，窗口标题26–28。常规按钮最小高度42像素；间距12，外边距16，弹窗外侧22–26。所有公共按钮的悬停、按下、禁用和键盘焦点共用可直接在 Godot 编辑的 `PrototypeTheme.tres`，不再由控制器临时生成主题。

若后续更换美术风格，先编辑共享 Theme；窗口和按钮可将 StyleBoxFlat 替换为 StyleBoxTexture 并设置九宫格边距。`UIStyle.gd` 仅保留临时地图绘制调色板和主题兼容入口，不是控件样式的另一份来源。纸纹、毛边、正式怪物和粒子材质尚未加入，不应把当前平色线框称为最终美术资产。

## 公共组件与层级

- WorldView：连续背景与地点标记，不画六边形格线，不承担地图移动。
- RuneBoard：61格输入面；符文书小图只画局部形状，不缩成难以辨认的61格盘面。
- MonsterPortrait：运行时矢量纸偶占位，不使用参考游戏截图或第三方单位贴图。
- 怪物卡：形象 → 名字与状态 → 属性 → 特性 → 详情／分配操作。
- 详情：只展示这一只实例的数据，可改名；特性继续打开说明，关闭说明回详情。
- 弹窗：统一纸底、铜边、顶栏返回；最上层可交互，下面仅作上下文。

## 交互规范

必须/MUST：当悬停可操作元素，则展示文字说明或明显悬停；禁用不能只换颜色，应提供原因。

必须/MUST：当打开说明窗，则不继续事件、不移动队伍、不重新生成产出；关闭回来源。

必须/MUST：当结果关闭，则未安置怪物入库，不能消失。

必须/MUST：当清空法阵，则先确认；取消不改变当前布局。改名在点击保存前不落盘。

应该/SHOULD：复杂特性数量增长时使用滚动与摘要，不无限压缩字号。640宽手机布局不作为本轮目标。

## 场景化与适配约束

基础信息：`UI_MAIN_WORLD` 为主界面，`UI_POPUP_RITUAL` 为召唤窗口；入口为地图书本，父界面为大地图。返回关闭最上层窗口，不切换到网页。

- 必须/MUST：当点击地图右下角书本，则打开召唤法典，且遮罩禁用底层操作。
- 必须/MUST：当刻入列表变长，则只增加左侧滚动内容，且中间阵面保持正方形与原位置。
- 必须/MUST：当窗口尺寸改变，则整体等比缩放1280×720设计画布；非16:9留边，禁止非等比拉伸。
- 必须/MUST：当调整组件资源，则同类实例使用共同变化；程序不得在刷新数据时重新指定组件尺寸、边距或贴图。

召唤组件：`RitualPanel.tscn` 定义 Columns、LeftScroll、BoardFrame、RightScroll、Summary、Controls。左右默认最小宽210／260；BoardFrame 使用 AspectRatioContainer（比例1，Fit）；Summary预留56高，Feedback预留50高。正文最多两行，避免内容引发布局跳变。修改字号后应同步预留文字高度并运行布局回归。

整体缩放是统一适配策略；不通过反复改变各节点的 `scale` 适配。独立调试窗口无需改业务代码。具体编辑路径、贴图插槽与组件工作台见 `04_UI组件可视化调整指南.md`。
