## 基础信息与目标

适用当前 `Scenes/GameDemo.tscn`，不适用旧0.1导航示意。所有路径为本独立工程的 `res://` 路径。目标是在 Godot 编辑器中维护界面布局、大小和美术接入，让美术与策划无需修改业务逻辑即可调整视觉；控制器只绑定节点、填入数据和处理操作，规则与存档继续独立维护。

先打开 `Scenes/UI/UIWorkshop.tscn` 查看组件，F6仅运行预览，不加载和保存游戏进度。F5运行完整流程。需要持久修改时双击组件源场景，不要把工作台中的临时实例修改当成正式改动。

## 改尺寸的方法

1. 容器里的节点由容器排布。调整 `Layout → Container Sizing`、`Custom Minimum Size`、拉伸比例和容器的 `Theme Overrides → Constants → Separation`。不要反复拖位置或修改 Scale，这些位置会被容器重新计算。
2. 地图上的书本和地点标记不是容器内列表，使用锚点与 Offset 调整。书本右下锚定，增大时建议同步修改左／上偏移，保持右／下内缩。
3. 左右滚动栏可以改宽，但不要设置内容撑高外层的尺寸。中间 BoardFrame 保留比例1和Fit，不要把方阵变成非等比拉伸。
4. 当前设计画布1280×720。窗口整体等比缩放，4:3或超宽窗口留边；这是主动选择，不是手机自适应重排。修改基准画布后需要重新核对所有布局。
5. Summary和Feedback预留两行高度；更改字体后同步修改最小高度并运行布局检查，防止长提示挤动阵面。

## 接入美术素材

- 书本：把 PNG/WebP/SVG 拖到 Icon 的 Texture；Expand Mode保持Ignore Size、Stretch Mode保持Keep Aspect Centered，避免图片原始分辨率撑大按钮。根按钮是点击范围，子图标忽略鼠标事件。
- 纸窗与按钮：纸雕主题现使用独立StyleBoxTexture与分件素材，具体切片和导入尺寸见Assets/UI/PaperRelief/README.md。先换对应Texture，再核对九宫格和内容边距。不要每个页面复制一份主题，也不要改控制器实现贴图。
- 怪物：给 Portrait/Artwork 的 Texture 赋透明贴图，自动隐藏参考插图和矢量占位。控制器只更新 Form/Tint与文字，不覆盖 Texture。本轮新增 ReferenceArt 展示用户概念原图，ReferenceCaption 必须注明不是生成结果；关闭 Use Reference Examples 回到矢量占位。显式 Artwork 不被参考图替换。正式每个怪物实例的不同美术由后续资产ID适配，不以改名字匹配贴图。
- 法阵：Board Texture承接正方形底图，蜂窝和笔画继续由独立 RuneBoard绘制；61格输入识别不是普通UI贴图，仍需规则脚本。底图要为蜂窝留出空间，勿烘焙重复格线。
- 大地图：Backdrop/Texture承接地图组回收的展示底图，仅世界模式显示；当前只是视觉接入口，不引入移动、寻路或地点真实坐标。

## 交互与代码边界

必须/MUST：当点击书本，则打开召唤法典；返回关闭最上层，且底层地图不能穿透点击。

必须/MUST：当增加列表项，则实例化公共 `.tscn` 并填数据，不能在业务脚本中重新生成容器、尺寸或样式。可动态增加多少行由数据决定，不要求在编辑器里预放全部怪物。

必须/MUST：当修改贴图或组件尺寸，则刷新业务数据不能重置它。共享修改编辑组件源场景，局部差异使用实例覆盖或继承场景。

必须/MUST：当移动节点层级或改名，则保留控制器所用唯一节点名（带 `%`），或同步更新绑定并回归；不要删除按钮所需节点。程序仅可切换状态所需的可见性、禁用、滚动模式和填充方式。

`GameDemo.gd`：流程、节点绑定、数据与操作；`PrototypeState.gd`：业务和保存；`RuneRules.gd`：识别规则；`RuneBoard.gd`：绘制与输入；`.tscn/.tres`：布局和视觉。怪物占位、法阵输入和喷涌仍有独立自绘脚本，不代表整套UI依然由一个脚本生成。画板进出已有独立AnimationPlayer；正式角色动画或物理接入为后续工作。
