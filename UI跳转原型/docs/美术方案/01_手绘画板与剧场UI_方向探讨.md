# 手绘画板与剧场 UI · 方向探讨

2026-10-11后续确认：用户选择A。A分件美术和画板进出已在独立原型试做，见[02_A方案_素材分件与效果测试](02_A方案_素材分件与效果测试.md)。以下保留当时提案和建议，不表示B／C或幕布已制作。

## 基础信息

类型：UI／美术资产／转场动画；优先级建议A；没有已确认的制作期限。本轮交付为方案，不生成正式贴图，不替换当前界面，也不修改正在由其他成员维护的美术讨论稿。

已确定的约束：UI使用Godot原生场景组件、可视化调整；召唤与仓库分属独立业务系统，公共视觉共用；大地图书本打开召唤，仓库可独立打开；转场不得擅自增加进入小地图的流程。

## 设计目标

把界面表现成可被翻阅、拉开和搬动的实物，而不是常规软件窗口。以手绘纸张承载信息，以画板和舞台建立空间关系，让怪物如同登台的纸偶；文字、数值和按钮仍清楚稳定，装饰与动画不能妨碍法阵输入或高频仓库管理。

## 三个方向

| 方向 | 主体与空间 | 召唤表现 | 仓库表现 | 标志性转场 |
|---|---|---|---|---|
| A 巡游画师的工作台 | 粗木画板、夹纸、铜钉、炭笔轮廓、少量水粉；正面浅层构图 | 书本翻开，法阵纸被夹到中央画板；奇物与符文分别在两侧便签 | 怪物肖像与档案卡被夹在大画板上，详情是一张移到前景的独立画纸 | 抽出旧画纸、推入新画板；轻微落位回弹 |
| B 掌上神话纸剧场 | 手绘台口、布幕、分层纸景、聚光；正面2–3层景深 | 法阵像舞台底盘，结果怪物逐只登台；喷涌是本地战场中的正式演出 | 后台角色名册与立片卡，查看详情时角色移到聚光区 | 闭幕遮挡切景，再把幕布向上拉起 |
| C 神祇的巡回画廊 | 浮雕感粗画框、悬挂画布、褪色壁画、墨线金色符号；较克制庄重 | 书本像导览册，法阵是可揭开的仪式画；生成结果逐幅揭幕 | 妖兽被装进有姓名签的手绘画框，详情是一幅拉到眼前的肖像 | 一幅画沿轨道移开，露出后一幅；揭开覆在画框上的布 |

### A · 巡游画师的工作台

第一眼是“有人带着工具在旅途中记录和召唤怪物”。不做写实厚木纹，而用平涂、可辨认的笔触、两档线宽和少量铜钉。纸边可以不规整，正文区域必须平整。现有青绿／纸黄／墨色／铜色可以继续使用。

召唤中央纸与两侧便签是不同组件；怪物卡与说明窗也使用同一套纸边。打开界面不是整张截图放大，而是外层画板滑入，内部信息落位后保持稳定。

优势判断：最适合先验证组件替换，装饰可复用，日常操作轻巧。风险：只堆纸纹与木框容易变成普通复古UI，需要依靠“夹纸、移画、铜钉”形成一致动作语言。

### B · 掌上神话纸剧场

第一眼是“玩家在操作一座会演神话的小剧院”。台口与幕布是手绘剪裁形，避免写实丝绸和金碧辉煌的大剧院；青绿或暗蓝幕布与纸黄背景可以保持现有色彩连续性。怪物仍是纸偶，不将UI做成真实3D剧场。

世界地图与战场可以是舞台中的换景板；召唤结果像纸偶登场。但在大地图打开召唤或仓库仍只是覆盖界面，不增加真实场景进入。小地图喷涌沿用既有玩法流程。

优势判断：与纸偶怪物统一，召唤仪式辨识度强。风险：全页面加厚台口占空间，每次操作都闭幕会拖慢节奏；仅在主要场景切换和重要演出使用完整幕布。

### C · 神祇的巡回画廊

第一眼是“怪物是被收录、唤醒的神话肖像”。画框用粗笔描边和木刻符号，而非写实奢华金框。比A更庄重、比B更安静，适合突出怪物来源与特性。画内有纸纹，数值区仍留干净底色。

仓库卡片像小幅挂画，选中后沿轨道前移；详情是一幅画移到前景，不必模拟真实透视。法阵与怪物肖像共享神话符号装饰，但不把可读符文藏进复杂边框。

优势判断：契合怪物收集与“移开图画”的交互。风险：大画框可能吃掉信息空间，不同AI画框容易不统一；必须以同一框架复用，不能每卡随机出框。

## 推荐组合：A为界面底层，B为主要演出

这是建议，不是已确认定案。推荐日常界面采用A的画板、纸签和铜钉，主要场景与召唤演出采用B的台口／幕布；把C的“移画”动作保留作详情或仓库切换的备选，不同时混用三套画框材质。

统一规则：同一纸色、墨线、铜钉与青绿强调色；只有换景层承担完整舞台装饰。不要让召唤负责人做一套神秘法书UI、仓库负责人另做一套现代卡牌UI。

## 转场分层

以下时长是试做参数，不是已实现效果或最终定值。

| 使用场景 | 动作 | 建议时长 | 输入与信息原则 |
|---|---|---|---|
| 大地图↔战斗等主场景 | 幕布先遮住内容，切换后向上拉起；台口不动 | 总计约0.55–0.75秒，不含加载等待 | 仅遮挡阶段换景，不显示未准备好的内容 |
| 打开召唤／仓库 | 画板从屏外或后层滑入，纸签随主体入场 | 约0.22–0.35秒 | 画板内部不缩放重排；沿用原生弹窗与底层禁用 |
| 召唤与仓库之间切换 | 当前画板移开，下一块从相反方向进入 | 约0.25–0.40秒 | 不能因此把两个业务系统合成一个；返回来源明确 |
| 怪物详情／术语说明 | 小纸片前移或抽出，正文出现后稳定 | 约0.12–0.20秒 | 不闭幕，不改变怪物数据，不让正文持续晃动 |
| 仓库筛选／高频卡片变化 | 小幅平移或短淡入 | 约0.08–0.15秒，或无动画 | 保持列表定位，避免逐张长动画 |
| 召唤喷涌与结果 | 当地演出完成后结果画板滑入 | 喷涌沿用当前2.8秒可跳过；结果入场约0.25秒 | 产出早已保存；动画结束只展示，不重新生成或扣费 |

不能所有跳转都使用幕布，也不建议每次移动卡片都播放完整“移画”。建议主场景一种重转场、系统面板一种轻转场、说明一种极轻转场。

## 动效组件方案（待实现）

建议由公共UI层提供两个独立场景：幕布换景组件和画板进出组件；名字和目录等选定后再落实。各系统只调用公共开关过程，不复制动画脚本或主题。

- 幕布：前景幕布、挂杆／拉绳和遮挡层分别出图；上下移动为主，不依赖真实布料模拟。支持“盖住／已盖住／揭开／完成”，盖住后才能切换显示内容。
- 画板：外层MotionRoot负责进出，内层Container负责布局；主体可有极轻微倾角，文字与法阵落位后不摇摆。
- 动画在Godot的AnimationPlayer中可视化编辑；不把时间、材质和所有关键帧硬写进某一个业务脚本。
- 动效不修改窗口设计尺寸，不靠反复改Scale适配。阵面落位后再启用输入，防止移动中画线错位。
- 动画进行中防重复点击；完成后恢复正确焦点。场景加载较慢时允许幕布停在关闭状态，不提前露出空白。
- 应提供快速／简化动效选项；业务保存、安置与发奖不依赖动画完整播放，也不因跳过动画重复执行。

以下只是可选方案的最小试做包。先选方向，再产出资产；不为三套方向同时制作完整UI。

| 资产ID | 主体／构图 | 功能要求 | 建议优先级 |
|---|---|---|---|
| ui_common_paper | 正面浅色手绘纸底，低对比纹理 | 可平铺或九宫格；正文区干净 | S |
| ui_common_board_frame | 正面画板边与四角，木质平涂、铜钉 | 边框与内容分离，适配不同大小 | S |
| ui_common_button | 纸签或笔刷色块，保持规则点击区 | 常态／悬停／按下／禁用轮廓一致 | S |
| ui_summon_book | 开本轮廓与独立页片 | 无文字，透明底；接现有书本组件 | A |
| ui_summon_board | 仪式纸与可选外环装饰 | 不烘焙交互蜂窝、笔画与数值 | A |
| ui_inventory_card_frame | 怪物肖像画纸／画框 | 图像、姓名签、数值栏分别放置 | A |
| ui_common_curtain | 手绘幕布，正面，不做写实褶皱 | 与挂杆、拉绳分件；运动区域留裁切余量 | A，选择剧场方向后制作 |
| ui_common_stage | 台口、角饰、浅层背景板 | 各层独立透明图，不能遮挡正文和按钮 | B |
| ui_common_marks | 铜钉、夹子、纸签、分页箭头、选中标记 | 少量反复复用，统一线宽与光向 | A |

技术规格建议：以1280×720设计画布为基础，首轮按可见尺寸约2倍绘制并裁切；PNG透明底为主，简单图标可SVG；九宫格记录切片和安全边距。并非每项都要一张全屏大图。交付可编辑分层源文件、导出图、命名表、切片说明和生成／修订记录；明确哪些是AI候选、人工整理版和实际接入版。

暂定视觉：纸黄、深墨、青绿、铜色；正面浅层构图；焦点为法阵／怪物与操作，不是幕布装饰。没有指定外部参考作品，本稿是项目内原创方向提案。

## AI资产的统一与去AI感

1. AI主要做纸纹、笔刷边、幕布、画框和装饰候选，不让AI生成可交互文字、数字或整张不可拆界面。
2. 先定少量母版：一种纸底、一种边框、一套铜钉和两档描线。后续组件复用母版，不每个页面重新抽风格。
3. 人工校正轮廓、透明边缘、对齐和留白；保留受控的不规则，不保留难以解释的随机污渍和伪文字。
4. 用真实资产和组件层次形成特点，而非只加纸纹滤镜。手绘边缘遮罩可以试，但正文、数字与法阵命中范围不受抖动影响。
5. 纸纹静止，避免全屏持续噪声与每帧随机轮廓跳动；不把“手绘”做成读数困难。

## UI交互验收

screen_id：`UI_MAIN_WORLD`、`UI_POPUP_RITUAL`、`UI_POPUP_WAREHOUSE`及公共转场层。入口与返回沿用当前原型。

- 必须/MUST：当点击书本或仓库入口，则显示对应独立系统面板，且不额外进入小地图。
- 必须/MUST：当完成进场，则文字、按钮与法阵稳定；可视位置与输入位置一致。
- 必须/MUST：当跳过或简化动效，则保存、扣费、产出与安置结果不变。
- 应该/SHOULD：当连续使用筛选或说明，则使用轻动效或无动效，不强迫反复观看完整幕布。
- 必须/MUST：当两位系统负责人各自换皮，则共享边框、按钮和转场来自公共组件，不能复制出互相漂移的版本。

关键元素：`btn_summon_book`（button，ui.summon.open）、`btn_warehouse`（button，ui.warehouse.open）、`img_curtain`（image，ui.transition.curtain）、`img_board_frame`（image，ui.common.board）、`lst_monsters`（list，ui.warehouse.monsters）。这里只是方案命名，未声称已新增这些节点。

## 选择后再做什么

建议先做一套最小视觉试片：大地图书本 → 召唤画板进场 → 已有怪物卡／仓库画板移开；另演示一次主场景闭幕与拉起。先看同一套资产在两系统是否一致，再铺开其他界面。

待用户选择：主视觉更偏A的工作台、B的纸剧场，还是C的神话画廊；幕布作为主转场还是仅召唤仪式使用。本轮未生成效果图、未制作动画、未改当前主题。
