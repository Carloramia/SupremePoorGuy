# 系统接入适配与联调协议

核对日期：2026-10-13。对象：UI跳转原型0.7.6。本文按当前磁盘代码编写；“已实现”和“接入建议／待实现”严格区分。此轮仅更新交接文档，不修改正式工程、事件工程、规则或存档。

## 1. 当前适配结论

**展示组件可复用，业务流程可独立验证；正式系统还需要宿主适配层，不是即插即用插件。**

| 系统 | 当前已具备 | 正式接入还缺什么 | 接入程度 |
|---|---|---|---|
| 公共UI、A1/A2、C/D/E | 原生场景、组件信号、弹窗栈、纸页动效、窗口适配 | 宿主输入／暂停／路由归属、资源路径迁移 | 表现层可复用 |
| 召唤 | 61格输入、符文／奇物、布局v2、测试扣费生成、pending恢复、结果安置 | 正式生成器、环境权重、统一事务与真实怪物实例映射 | 原型闭环可用；生产生成未接 |
| 仓库／出战 | 按ID筛选、详情、改名、出入队、回收、失败回滚 | 正式库存服务、战斗部署和回收政策、完整属性映射 | 展示可接；当前仍用原型库存 |
| 地图／地点／时间 | 点击地点信号、悬停概况注入、结束事件隐藏 | 抵达／可进入判定、真实地点ID、日历／天气／下一事件上下文入口 | 仅占位地图及少量展示接口 |
| 战斗 | 点击直达小地图、队列通知、结算后降下大地图 | 战斗加载、开始／结束回执、胜负／伤亡／奖励、退出恢复 | 尚无真实战斗接入 |
| 事件／任务 | 大容量正文、固定选项、一次性奖励、离开、完成图标移除 | 节点执行、条件、分支、任务阶段、持久会话和通用奖励适配 | 单一事件演示，非叙事运行时 |
| 存档／经济 | 独立保存、备份、写入失败回滚、原型奖励去重 | 正式存档统一所有权、版本迁移、请求账本 | 仅独立原型存档 |
| TA／美术 | 公共／局部材质预设、分层资源槽位、恢复、独立测试场景 | 最终S1/S2/S3 Shader、素材、性能与视觉验收 | 接口已预留；最终材质未交付 |

不能将“已有信号”解释为宿主已能完全接管；也不能把示意属性、动画、占位场景当成正式业务实现。

## 2. 工程边界与接入方式

原型入口：`project.godot` → `Scenes/GameDemo.tscn`，Godot4.7.2、GL Compatibility、原生窗口布局、最小1120×680。原型无Autoload。

本地正式候选工程 `../it-is-time/project.godot` 声明4.7、C#、Forward Plus，并有DamageService、WorkshopUIController、RuntimeConsole等Autoload；窗口使用canvas_items/expand。这说明引擎大版本接近，**不能据此确认渲染、C#运行时、输入或窗口缩放兼容**。正式工程须用其自己的运行环境验证；不要把原型project.godot、Autoload和窗口配置整体覆盖过去。

建议分两步接：

1. 先复用纯UI场景、主题和Scripts/UI组件，在正式宿主下用展示快照驱动，验证输入、尺寸与材质。
2. 由集成人员替换GameDemo中的测试分支与PrototypeState数据来源，再逐个接真实服务。GameDemo不是可直接发布的通用UI SDK。

资源目前引用 `res://Scenes`、`res://Scripts`、`res://Assets`。若迁到 `res://Modules/UIPrototype/`，必须成批重写内部引用并验证；这个前缀是建议，尚未迁移。复制时保留.uid/.import元数据，不复制.godot、Tests/.runtime或个人存档。

## 3. 当前真正存在的接口

### 宿主通知：GameDemo.gd

| 信号 | 触发时间 | 必须注意 |
|---|---|---|
| location_interaction_requested(location_id, kind) | 测试地图点击后，处理事件或战斗之前 | 不等于抵达，不做真实距离判定；返回值不会取消后续逻辑 |
| scene_requested("battle", location_id) | 点击战斗标记，随后原型仍执行_show("battle") | 仅监听会造成正式宿主与原型双路执行，须替换测试路由分支 |
| scene_requested("summon", location_id) | 测试生成与保存已经成功，随后执行喷涌 | 不得在监听器再次扣费或生成 |
| party_changed(monster_ids) | UI成功移动或回收后通知 | 直接调用PrototypeState不会自动发此信号；正式服务提交后统一刷新 |

`_show/_modal/_open_ritual/_warehouse/_open_event/_results/_skip_battle` 均为控制器内部方法，不承诺稳定的跨工程服务API。`_skip_battle`只供测试调用，玩家界面没有跳过战斗按钮。

### 可复用展示组件

| 文件 | 输入／方法 | 输出 |
|---|---|---|
| Scripts/UI/NavigationPanel.gd | present_context(in_battle, animate) | action_requested：tasks/summon/warehouse/party/world/dictionary/help |
| Scripts/UI/WarehouseView.gd | present_filters(position_id, forms:Array[String], counts, animate) | back_requested、position_filter_requested、form_filter_requested、clear_filters_requested |
| Scripts/UI/MonsterNote.gd | present(id,title,form,position_label,hint)、set_selected(selected) | selection_requested(id) |
| Scripts/UI/WorldView.gd | configure(mode,id,units)、set_location_previews(previews)、set_unavailable_events(ids) | location_clicked、ritual_requested、eruption_finished |
| Scripts/UI/BookmarkSlot.gd | set_present(present,animate,delay) | 仅动效，不执行业务 |
| Scripts/UI/FilterTab.gd | set_active(active,animate)；原生icon属性可替换文字 | 继承Button事件 |
| Scripts/UI/BoardMotion.gd | reveal/dismiss/snap、enabled | completed(kind)，仅视觉完成 |
| Scenes/UI/Screens/EventPanel.tscn | %Description文字、%Commands按钮区 | 选项回调由宿主绑定；不是事件执行器 |

展示更新不发起业务请求，程序填入筛选状态不会反向触发奖励或库存修改。所有装饰／材质层忽略鼠标输入。详细材质契约见[06_组件隔离与TA材质接口](06_组件隔离与TA材质接口.md)。

地点概况实际输入示例（不是默认真实地点数据）：

```gdscript
view.set_location_previews({
    "desert": {
        "tags": "【沙漠】【沙】",
        "types": "兽形 / 蛇形",
        "abundance": "少量"
    }
})
view.set_unavailable_events(["traveler"])
```

当前地点ID为grassland/forest/desert，事件ID为traveler；正式地点ID须建立映射。缺少侦察数据时显示待侦察，不随机编情报。天数、天气、魔力、下次事件尚无统一上下文DTO入口，当前是控制器字段／原型State；正式接入要补快照适配并替换_update_header/_refresh_ritual的数据源。

## 4. 召唤与生成器对接

### 已实现数据

RuneRules.export_layout返回：

```json
{"version":2,"placed":[],"placedRelics":[]}
```

placed元素：uid、runeId、cells（二维轴坐标数组）、enabled。placedRelics元素以RuneRules实际导出为准，含relicId、cells等；不要把贴图或UI像素位置当作生成输入。import_layout接受v1/v2并校验已知形状，导入时重建局部uid、过滤不合法项；**返回true不代表每条输入都原样保留**。正式资产有额外定义时先建立规则ID映射，不能依赖r1等局部uid作跨存档身份。

PrototypeState.summon(rules, location, return_route)是当前同步测试事务：校验草稿／启用符文／魔力／pending → 扣费一次 → 生成3只测试怪物 → 保存怪物与pending → 成功后喷涌 → 安置同一批实例。队列上限6、批次3、初始魔力300是当前原型参数，不是对正式系统的不可变要求。

### 正式替换位置

- 替换GameDemo._summon和PrototypeState.summon内测试随机生成；不要只接scene_requested。
- 先确定请求ID、布局快照、地点／环境快照与生成批次ID，再由同一服务提交扣费和产出。异步生成时需补忙碌、失败、取消、重试状态；这些API目前未实现。
- 成功持久化实例和pending后才能播放喷涌。重启恢复pending只展示已有实例，不重抽、不再扣费。
- 演出失败或被跳过不能丢失产出，结果页移动同一个monster_id。

本地 `../it-is-time/Scripts/Creatures/Generators/BaseCreatureGenerator.gd` 是Node3D工具生成器，确有 `framework_generated(plan)`、generate_torso()、generate_framework()等入口。它不是原型summon服务，也没有已验证的“RuneRules布局→生成plan→唯一库存实例→战斗单位”桥梁。接入方需确认plan格式、正式资源ID、生成失败和实例生命周期；本次只核对入口存在，未运行其生成或修改主工程。

## 5. 仓库、队列与怪物映射

当前怪物展示／存档必需字段：

| 字段 | 当前类型／含义 | 正式适配要点 |
|---|---|---|
| id | 非空String，唯一实例ID | 名称可改，不能以名称或列表位置关联 |
| name | String，改名去首尾空白、截至24字符 | 由正式服务验证并提交 |
| form | 人形/兽形/蛇形 | 目前仅三类；其他形态需映射或扩展UI筛选／头像 |
| hp/attack/armor/speed | 有限、非负数值 | 现为展示测试值，不能直接当真实伤害公式 |
| traits | Array[String] | 当前为展示名称，正式效果ID需单独映射 |
| position | pending/warehouse/team | 状态迁移由统一库存服务决定 |
| color | HTML颜色字符串 | 占位颜色，正式外观应用资产ID，不通过名字猜图 |
| source_location/source_layout | 可选溯源字段 | 当前生成会填，历史存档不保证存在 |

State现有方法：monsters(position="")、monster_by_id(id)、move_monster(id,position)、rename_monster(id,name)、store_pending()、recycle_monster(id)。move只能到warehouse/team；成功后从pending移除。回收拒绝pending，不返魔力，当前政策必须由正式系统确认。均要检查bool与last_error，失败不可先删UI。

UI展示层已拆出WarehouseView和MonsterNote，但筛选后的怪物列表、详情、动作绑定仍由GameDemo组织；这不是完成了独立库存插件。接正式库存时，订阅其变更快照，再重新填充视图；不要保留第二份可独立修改的原型库存。战斗部署应按id查询正式实例，并保证属性、资源和单位回执对应同一ID。

## 6. 地图与战斗对接

现有WorldView是占位绘制，不负责导航、地图加载、碰撞或战斗模拟。正式地图应替代它的移动和场景职责，可复用A1/A2、地点卡和书页界面。

需由负责人新增的协议（**建议字段，尚非现有API**）：

- 战斗请求：request_id、location_id、party_ids、来源场景／恢复位置。
- 加载结果：同一request_id、success/error；失败恢复UI，不启动占位战斗。
- 结束回执：battle_id、胜负／退出原因、最终队伍状态、奖励请求ID、结算展示数据。
- 结算确认：正式服务已提交后关闭结算；大地图下拉遮住小地图；动画完成后恢复地图交互。动画不是发奖依据。

必须替换_location_clicked的测试_show分支，并接正式结束回执；不能继续靠_skip_battle触发结算。现阶段没有通用receive_battle_result之类API，也没有伤亡、战利品和战斗中存档适配。退出／失败／快速点击／重读档都要测；真实战斗是否暂停、切场景由宿主统一负责。

## 7. 事件与任务对接及本地缺件

当前旅人手记是硬编码事件，不解析事件JSON。EventPanel只是正文和固定选项布局。领取时调用claim_once("event_"+id,20)，成功后标记完成；EVENTS.has_followup=false时隐藏图标。离开不标完成，失败不隐藏；这不能替代完整任务阶段和分支持久化。

当前事件工具README说明正式导出根字段为schema_version/id/title/start/reward_mode/nodes，节点含对白／选择／奖励／结束；UI原型尚未消费这个格式。

**本地交付缺件，需事件负责人先补齐：**

- `../事件配表工具/Godot事件表现/README.md`列出core/event_session.gd、core/event_json_port.gd、core/event_definition.gd等。
- 核对当前磁盘，上述core文件不存在；ui/event_window.gd却preload了core/event_definition.gd。因此不能宣称本地事件工程已可运行或Session接口已经可导入。
- 实际存在的ui/event_window.gd有open_event(definition,session_id)、reward_requested、choice_selected、acknowledge_reward和event_closed；但受缺失依赖影响，本轮没有验证其运行。

补齐后按统一事件执行器适配，不复制两套推进逻辑。奖励由正式奖励／存档服务按持久request_id去重，成功提交后再回执；失败保留等待态。event_closed与abort_event须区分，不能关闭就算完成。任务、事件完成、奖励账本、后续分支可用性分别保存；仅当已完成且确无后续才移除地图标记。原型completed数组不够表示完整任务阶段。

## 8. 存档、经济与错误语义

当前保存版本1：version、magic、serial、monsters、pending、pending_location、pending_return、completed、layout；解锁后可能增加known_runes/known_relics，旧档缺省通过known_references回退。原型路径user://prototype_session.json，自定义用户目录SupremePoorGuy_UIPrototype。测试走Tests/.runtime独立文件。

PrototypeState负责.tmp写入、旧档.bak、替换和失败回滚；load_save尝试主档及备份。它不是正式账户库存，也没有联网、并发锁、跨设备事务或通用事件奖励账本。

正式接入前确定一个状态所有者：魔力、怪物、队列、pending、事件进度、奖励去重必须一起规划。不得让原型State与正式服务各写一份。同一次奖励不要用“先加魔力、后写账本”分两次保存；生成也要明确失败是否退款与重试幂等。持久ID／事件session ID不能每次打开随机重建。迁移须先备份、验证版本和引用完整性，再切正式入口。

| 顺序 | 牵头角色 | 完成标志 |

| 5 事件与任务 | 事件负责人 | 缺件补齐、JSON节点执行、奖励回执及后续状态通过 |
| 6 最终材质 | TA／UI美术 | 独立预览通过，S1/S2/S3回交及正式工程视觉／性能验收 |

每位负责人回交：修改文件清单、实际调用／信号及字段映射、资源依赖、成功与失败示例、测试证据、未完成项。GameDemo、PrototypeState、公共主题和共享场景由集成人员统一协调修改。

## 10. 最低验收与当前证据

- 移动／抵达与图标点击关系清楚，不绕过正式地图判定；A1显示正式上下文。
- 召唤确认不能连点重复扣费，pending重启恢复不重抽，生成失败／保存失败不丢库存。
- 同一monster_id在结果、仓库、队列、真实战斗往返，改名／满队／回收失败不复制或丢失。
- 战斗只切一次场景，结束只结算一次；结算确认后地图下拉，失败退出有恢复路线。
- 事件离开不标完成，发奖失败可重试，同一请求不重复发奖；有后续的完成事件不误删。
- 1120×680至1920×1080、长列表、长事件、4个选项、鼠标和键盘、快速开关、简化动效通过。
- 最终材质不影响文字、点击区、法阵连通或布局，不重抽纹理种子。

原型现有专项：ValidateNativeUI、ValidateUILayout、ValidateArtUI、ValidateSketchRevision、ValidateReadability、ValidateA2Motion、ValidateFilterTabs、ValidateSketchMotion、ValidateComponentContracts、ValidateEventPanel、ValidateLocationHint、ValidateEventLifecycle；静态边界ValidateIsolation.ps1。各测试在独立路径运行，不用正常存档做fixture。

历史回归已覆盖上述原型行为；**不等同于正式工程、缺件事件工程或最终Shader已通过**。本轮文档核对未修改运行代码，不因补文档重复宣称新增运行验收。正式接入完成后，需在宿主补真实模块的成功、失败与恢复测试。
