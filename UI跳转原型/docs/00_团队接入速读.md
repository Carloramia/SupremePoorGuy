## 当前流程

左侧书签打开召唤／仓库；C与D为独立纸页。战斗地点悬停显示概况，点击直接进入占位小地图；没有玩家可点击的跳过战斗按钮。事件采用扩大正文区和固定选项，完成且无后续的事件图标消失，离开未完成事件不消耗机会。结算确认后大地图下拉遮住小地图。

## 必须先确认的接入事项

1. 谁唯一持有魔力、怪物实例、队列、pending、事件进度和奖励账本。
2. 谁控制真实场景切换。现有GameDemo信号是通知，测试分支仍会继续执行，需明确替换。
3. 正式生成器如何从布局和环境生成稳定实例；不能由演出再次生成。
4. 真实战斗结束如何回执，成功提交奖励后如何驱动结算及返回。
5. 事件工程core依赖缺失，先补齐并验证，再谈Session／JSON协议联调。
6. 正式工程C#／Forward Plus与原型GDScript／Compatibility、窗口缩放及资源路径差异如何处理。

接入顺序：资源与宿主 → 统一状态和存档 → 生成与库存 → 地图战斗 → 事件任务 → 最终材质验收。详见协议，不把建议协议名视为现有API。

交回时附修改文件、真实接口与字段映射、失败／重试／恢复测试、资源依赖和剩余工作。共享控制器／模型／主题由集成人员协调。不要复制个人存档、.godot或Tests/.runtime，不要覆盖正式project.godot。
