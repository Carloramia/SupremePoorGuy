## 已确认

1. 大小地图移动由其他组完成。本工程不做移动、路线、时间、缩放或寻路，回收后接入。
2. 当前地图只提供战斗与事件两类标记。事件在大地图直接交互，不能为读事件另建探索小地图。
3. 小地图只承担战斗及召唤演出。战斗先管理队伍，再跳过；不伪造实战统计。
4. 召唤可以直接从大地图打开。全部界面与功能在 Godot 内部实现，不打开网页，不使用 WebView。网页只用于规则与交互验证。
5. 每次召唤暂定3只占位怪物，队列上限6只。可查看生命、攻击、护甲、移速、形态和特性，可入库或编入队列。
6. 跳过战斗视为胜利并给予测试奖励；怪物、队列及领奖状态重启后保留。
7. 参考 How Many Dudes? 的属性摘要、怪物大形象、能力说明及术语解释层级，不移植其回合、招募、家族或经济系统。
8. 保持独立工程，原主工程、地图组代码、网页原型、其他事件工程和美术讨论稿不动。UI规范独立管理。
9. 用户批准仅在 Godot 原型修正疾风与双峰图案；网页不改，具体差异见规则移植说明。
10. 大地图召唤入口使用书本图标，位于地图右下角，点击后在原生界面中打开召唤法典。
11. UI 必须以可视化编辑的场景组件组织，方便修改大小、布局和接入美术资产；不能由一个脚本创建整套界面。

## 当前交互

- UI_MAIN_WORLD：点击战斗标记 → 概览 → 确认进入场景；点击事件 → 对话与一次性魔力领取。
- UI_POPUP_RITUAL：相邻格绘制、刻入、撤回、取消、奇物拖入／点放、启停、删除／回收、布局保存和清空确认。
- UI_MAIN_ERUPTION：保存本次产出后再播放2.8秒喷涌，可跳过；动画不负责生成或发奖。
- UI_POPUP_RESULTS：3张并列怪物卡，可逐只出战／入库，关闭将剩余产出全部入库。
- UI_POPUP_WAREHOUSE：仓库、出战、全部三个筛选，详情、改名、转移、队列满提示。
- UI_POPUP_MONSTER / TERM：属性与能力摘要，可继续打开术语说明；返回恢复上一层。
- UI_MAIN_BATTLE：管理队伍、召唤、跳过战斗、返回大地图。空队列不能跳过。
- UI_POPUP_SETTLEMENT：测试胜利与20魔力，按地点领取一次，重复进入不重复发奖。

## 测试参数，不是最终策划定案

- 初始魔力300；每个刻入符文格消耗1魔力，停用仍计费；奇物不计费。不做环境手续费、阶位或完整经济。
- 形态在人形／兽形／蛇形中随机，属性在受限测试范围随机；魔力不是实际怪物战斗强度计算器。
- 所有启用符文合并为结果特性标签。疾风给测试移速加成，骨骰随机强化一项测试属性；其余战斗效果只展示说明，没有真实交战承载。
- 7枚符文、3件奇物全开放。未收录符文隐藏、引导物进度、天气、环境生成权重和正式稀有度尚未接入。
- 地形、场景、怪物外形为绘制占位，不是正式地图资产和物理怪物。
- 本版本没有死亡、负伤、解契、交易、永久删怪或新游戏重置操作。不要把旧占位版中的请求按钮视为本轮已实现功能。

## 验收目标

必须/MUST：当点击有效地点时进入正确交互，且事件不进入探索场景。

必须/MUST：当召唤确认时先原子保存本次结果，再显示喷涌；重启恢复相同产出，不重抽、不二次扣款。

必须/MUST：当队列达到6只时禁止继续加入，且能改为入库；出入队列不能复制怪物。

必须/MUST：当领取战斗或事件奖励时只增加一次魔力；领取失败不显示成功。

必须/MUST：当弹窗存在时禁用底层鼠标和键盘入口；返回优先关闭最上层。

应该/SHOULD：1280×720下主操作、状态和3只基础产出能看清；多特性和长列表允许滚动，不裁切文本。

必须/MUST：当增删已刻入符文、显示长提示或返回召唤窗时，阵面不得随内容异常变大变小。两侧列表独立滚动。

必须/MUST：当美术调整组件场景的尺寸与贴图时，运行时不得把这些视觉设置重置为脚本中的固定值。列表数据由组件实例呈现。

当前适配策略：1280×720 设计画布、整体等比缩放、非16:9留边，不拉伸圆形法阵。不是手机端重排方案。
