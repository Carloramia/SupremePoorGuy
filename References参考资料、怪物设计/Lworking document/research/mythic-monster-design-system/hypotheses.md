# 候选方案

## H1 按神话地域分类

- 预期收益：资料组织直观，方便追溯文化来源。
- 风险：不能直接驱动身体组合、索敌和攻击；容易形成“换皮图鉴”。
- 证伪条件：无法从类别稳定映射到生成参数和玩法差异。

## H2 按传统物种分类

- 预期收益：四足、鸟、蛇、人形等轮廓易读，美术制作简单。
- 风险：复合神话怪物会被压平，无法表达异常结构。
- 证伪条件：大量候选需要塞入“其他”，或同类怪物行为过于相似。

## H3 多轴生成语法

- 预期收益：用身体拓扑、组合操作、移动介质、攻击器官、索敌动机和生态代价共同生成怪物，可直接落到数据表与 AI。
- 风险：轴过多会增加调参和 UI 说明成本。
- 证伪条件：Jam MVP 无法将轴压缩到少量枚举，或组合后不可读、不可平衡。

## H4 直接使用神话怪物名称与完整形象

- 预期收益：认知成本低，宣传容易。
- 风险：俗套化、文化挪用、与随机拼装机制冲突。
- 证伪条件：候选必须大幅改写才能进入系统，或专名压过玩家对部件和词条的理解。

## H5 将神话形象拆成设计基因

- 预期收益：保留熟悉感，同时允许重新组合；适合随机召唤和涌现。
- 风险：拆得过细会失去来源辨识度。
- 证伪条件：测试者无法描述怪物的主要视觉钩子，或不同来源组合趋同。
