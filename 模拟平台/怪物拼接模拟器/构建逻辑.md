## v0.6 兽形生成器接入

`beast.js` 最后加载并覆盖 `template('beast')`；人形和蛇形继续调用原模板。生成逻辑参照游戏工程中的 `CreatureGenerator.gd`，无需修改该文件或任何 Godot 场景。

生成顺序：参数与数量校验 → 固定种子的随机采样 → 主躯干上下轮廓与相邻连通 → 每脚独立 SubTorso → 脚表面间距 → 两段 ForeLeg／三段 Leg 拟合 → 肢段尺寸 → 颈线避障与旋转盒交集校验 → 肢端连通网络 → 二维结构装配 → 原 v2 导入校验 → 原子替换组合。脚／颈布局不合法最多整体重试 128 次；颈部每批最多尝试 128 次。所有布局与候选组合先在独立对象中完成，成功才写回 state；change 的失败保护负责保留原组合和历史。

主躯干 X 长度为 `bodyLength / (1 + (torsoCount-1) * (1-overlap))`；相邻中心间距为段长乘 `1-overlap`。四条曲线使用严格递增的归一化点，区间用零切线三次 Hermite 插值，对应默认 Godot 曲线的零切线。自定义 Godot 曲线的非零切线与切线模式未提供网页导入入口。参考高度采样一次，上下轮廓定义各段高与中心；高度偏移不改变段高。脚最小距离在 XZ 方向按表面间隙校验。

保留 X 向前、Y 向上、Z 左右的内部三维规划。显示采用 `x=(X+side*sideSpread)*40*overallScale`、`y=-Y*40*overallScale`。Z 不进入侧视形状，而是保存在 generatorZ，并决定层级。所有躯干、支撑、肢段、颈段 type=body，角色由 generatorRole 区分；head／foot 保留素材类型。连接树从尾部主躯干依次连至前部、支撑、倒序肢段、脚，以及颈头；用归一化连接点和补偿偏移保存精确初始世界位置。父级移动可带动后代，旋转仍遵循平台原来的独立部件角度规则。

生成参数位于 state.beastGeneration.settings，另存实际 seed、attempts 和网络；项目 schema/version 保持 monster-assembly/v2，作品保持 monster-work/v1。网页种子算法与 Godot 不同，复现只承诺网页内相同参数和种子的结果。网络是生成时的参考数据，手动编辑后不再与部件同步，selection=false 的 PNG／缩略图不绘制网络。

默认组合共 38 件：6 主躯干 + 6 支撑 + 12 后腿肢段 + 4 前腿肢段 + 6 脚 + 3 颈段 + 1 头。组合仍最多 60 件，宽度等旧编辑范围不扩展。兽形模式禁用原躯干数量控制（它包含结构件）；数量在生成参数中调整。占位素材来自尺寸对应的内嵌 SVG，每次生成清理旧自动占位素材并保留用户导入素材。无须安装外部库。

验证：`node tests/test_dynamic.cjs app.js`，68 项覆盖原交互与新的种子、布局、轮廓、支撑、分段、缩放、网络、保存、回滚和撤销行为。

# 怪物拼接模拟器构建逻辑

本文件随平台维护。它说明已实现内容、参数位置和交接约束；不把本工具的 2D 对齐规则当成游戏的物理关节设计。

## 基础信息与设计目标

界面为独立浏览器工具，入口为 `index.html`；左侧是素材与组合列表，中间为拼接画布，右侧为参数与记录，无父页面依赖。美术在物理接入前，用自己的素材验证身体、头、手脚和翅膀的尺寸关系、连接位置及遮挡。常用配置可通过文件独立保存、传递和恢复，接手成员能从明确的参数入口修改规则，不依赖口头说明。

## 连接与坐标

连接结构为无循环的多躯干树／森林。每件部件用 `parentId` 指向一个躯干、用 `mount` 指向该躯干上的接口；`parentId=null` 为自由放置根节点。躯干也可连接到另一个躯干，因此支持多节蛇身及分支；不支持把其它部件当作父节点。父级选择排除自身及后代，导入再次检查循环。

每段接口保存 `ports` 坐标、`portNames` 名称及兼容字段 `portTypes`。v0.3 的点不代表手、脚或任何部位，portTypes 统一 any，类型属于部件本身。模板和旧方案保留点位及挂接，移除旧的默认部位命名；自定义名称可保留。辅助素材库添加优先选择空闲点，缺点补点；右键挂接则严格使用所点的接口，不寻找其它点，也不自动增点。

## 画布右键交互（v0.3）

- MUST 当在躯干上右键，则菜单提供“在此新增连接点”，且点位由鼠标世界坐标逆变换到该躯干的归一化坐标，支持旋转、镜像及纵向缩放。
- MUST 当在可见连接点上右键，则无需预选躯干，直接提供挂接素材、解除部件及删点操作。连接点命中半径为屏幕 12 像素，优先于躯干像素命中。
- MUST 当选素材并挂接，则 parentId 指向该躯干、mount 使用点击的点；所有素材类型都可选择，同一点可挂多个部件。
- MUST 当删除点，则已有部件原地解除连接而非删除，可撤销；不选择素材就不会自动附加手脚。
- SHOULD 当点击菜单外部或按 Escape，则关闭菜单。右键 pointerdown 不触发左键拖动或写入撤销快照。

菜单元素：pointMenu（浮层）、contextAdd（增点）、pointAsset（素材选择）、contextAttach（挂接）、contextDetach（解除）、contextDelete（删点）、contextClose（关闭）。当前使用中文显示文本，无本地化系统。导航：右键躯干 → 增点 → 选素材挂接 → 左键拖点 → 右键再编辑／删除。

删点不删部件：先保存其世界位置，再解除父连接。删除躯干或减少躯干数量则移除其连接后代；多件删除有确认，可撤销。复制躯干保留外观，清空自身接口、解除父连接、不复制后代；单件导出仍保存用户布置的接口但不打包后代，导入保留该文件的明确配置，完整连接关系需整体导出。

身体接口用素材矩形范围内的归一化坐标表示。部件也有一个素材连接点，范围为 0–1。透明留白算在素材范围内，所以换图后可能需要重设连接点。

对齐流程：计算身体接口的画布位置 → 计算部件连接点经过尺寸、旋转、翻转后的偏移 → 让该连接点落在身体接口 → 加上手动偏移。身体旋转影响接口位置，但不让所有肢体自动继承身体旋转角；部件旋转独立可调。

层级 `z` 与连接位置无关。小数参数可保存；默认左右名称指工具接口，不替代正式游戏左右骨骼规范。按图片透明像素命中点击，便于选择前景部件的透明区域后方素材。

## 本地作品与层级组（v0.4）

### 画布平移（v0.5 补充）

MUST：当左键按住画布空白处，或中键按住画布任意位置并拖动时，则修改 view.x / view.y（屏幕像素位移），且不修改 state、所选组件或撤销历史。左键命中部件／点时仍进入原编辑路径；右键仍为布点菜单。松开、取消或丢失指针捕获时结束平移、恢复光标；其它 pointerId 不干扰本次平移。元素沿用 canvas（画布）、status（提示）与 fit（居中按钮）；路径为画布 → 拖动导航／滚轮缩放 → 编辑或居中复位。实现位于 app.js 的 beginPan、pointermove、endDrag；视野不进入磁盘作品和预览 PNG，图片导出独立按部件边界构图。

MUST 当点击保存作品，则将完整方案和透明缩略图写入本地作品文件，成功后显示磁盘保存状态。工作区缓存不等于作品文件。新作品使用随机 ID，更新用原 ID；另存创建新 ID。覆盖前保留历史备份，不提供删除／清空功能。

MUST 当点击作品载入编辑，则校验文件后恢复素材、连接点、部件名、层组及排序；覆盖当前工作区前确认，且可撤销。磁盘作品的编辑必须再次点击保存才写回。

MUST 当拖动部件／组，则改变前后遮挡，不修改 parentId 或 mount。state.layerGroups 按后到前排序；部件 layerId 指向组、layerOrder 决定组内后到前顺序。sorted() 是画布、命中和导出统一顺序来源。列表显示反向，故上方在前。z 在兼容输出中同步为组索引 + 1。旧文件缺少 layerGroups 时按旧 z 升序迁移，保留遮挡。

MUST 当组合列表改名或双击部件名，则打开 renameDialog；确认后仅修改 part.name，不改 asset.name。组标题同样可重命名，组名称不决定排序。拖动使用指针位移阈值 6 像素，释放位置命中目标部件／组；↑／↓ 和所属组选择提供替代操作。

作品格式为 schema=monster-work、version=1、id/name/updatedAt/preview/project；preview 为内嵌 PNG Data URL，project 仍为格式 v2，增加可选层组字段。每作品最多 64 MB。组件及传统项目文件导入仍受 15 MB 限制。组最多 40 个、部件仍最多 60 件。

服务接口：GET /api/works 列缩略图，GET /api/works/{id} 读取完整作品，PUT /api/works/{id} 保存。服务只允许指定 loopback Host 与同源 Origin（无 CORS），拒绝路径越界，使用临时文件原子替换并备份旧内容。HTML 文件入口不能静默写入工程，因此使用 showDirectoryPicker 授权，或启动服务；浏览器不支持目录选择时提示使用服务版。目录模式同样保存历史；该授权流程尚未做真实浏览器文件选择验收。

新界面元素：openWorkspace、workName、saveWork／saveWorkAs、chooseWorks／refreshWorks、gallery、newLayerName／addLayer、partLayer、renameDialog／renameValue／renameConfirm／renameCancel。导航：作品库 → 保存或载入 → 分组／拖动／改名 → 再次保存。文案直接中文，无本地化系统。

测试命令：node tests/test_dynamic.cjs app.js（34 项），python tests/test_server.py（5 项）。覆盖前后排序、改名与素材隔离、方案往返、磁盘保存读取、覆盖备份、越界及跨源写入拒绝。

## 接手修改参数

在 `app.js` 顶部的 `CONFIG` 集中维护默认配置：

| 配置 | 当前默认 | 影响 |
| --- | --- | --- |
| `defaults.body.width` | 200 | 新身体宽度；按图片比例计算高度。 |
| `defaults.head` | 宽 135，层 30，锚点 `[0.5,0.75]` | 新头部的对齐与前后关系；适配示例头部实际下缘。 |
| `defaults.arm` | 宽 92，层 20，锚点 `[0.5,0.1]` | 手部默认位置和层级。 |
| `defaults.foot` | 宽 90，层 5，锚点 `[0.5,0.08]` | 脚部默认位置和层级。 |
| `defaults.wing` | 宽 190，层 -10，锚点 `[0.88,0.75]` | 翅膀默认在身体后方。 |
| `ports` | 头、左右手、左右脚、左右翼共 7 接口 | 新身体接口；已有组件文件保存自己的接口，不被新默认覆盖。 |
| `maxFileBytes` | 15 MB | 单次读取文件上限。 |
| `maxParts` | 60 | 组合数量上限；修改时同步更新校验、导入和复制处的上限。 |

名称、宽度、旋转、偏移、层级、镜像、部件锚点和身体接口均可直接在页面调整。宽度范围 10–1000、层级 -100–100、旋转 -180°–180°。若改参数范围，同步输入控件、数值校验与文档。

v0.5 增补配置在 `dynamic.js`：`freshPart` 新建躯干时将 ports / portNames / portTypes 设为空；`addRaw` 对无指定接口的新躯干自由放置，不调用自动选点；`availablePort` 仅为主动添加肢体等操作寻找／补充接口；`templatePoint` 设置无类型的模板必需点位，`template(kind)` 用明确的 mount 键连接三类标准形态，`targetCount` 负责数量调整。人形仅 5 个必需点；兽形 1 头 4 足；蛇形首段 neck 接头、前五段 next 接后续躯干，末段无接口，后续段 anchor=[0.24,0.5]，前段 next=[0.77,0.5]，不自动镜像。不能依赖通用点的数组顺序推断标准模板连接关系。右键主动挂入躯干由 context.js 的 attachAtPoint 处理，新件自身仍无点、不自动镜像；用户可之后手动翻转。旧缓存和作品不自动重接，刷新后重新套模板（可撤销）才应用新结构。

躯干数量输入 1–20，每段每类肢体数量输入 0–10，整体仍最多 60 件；手动添加或复制受整体上限约束。每段最多 40 个连接点，纵向比例 0.2–4，实际高度 = 宽度 × 图片长宽比 × 纵向比例。修改这些范围需同步 HTML、处理逻辑及导入校验。

新控件：`bodyCount`、`humanTemplate`／`beastTemplate`／`snakeTemplate`、`parentBody`、`heightScale`、`portSelect`／`portName`／`portType`／`portX`／`portY`、`addPort`／`deletePort`，以及 `headCount`／`armCount`／`footCount`／`wingCount`。选中躯干并勾选显示连接点后可直接拖点，归一化坐标按逆旋转和镜像计算。

## 保存格式与留痕

组件文件：`schema=monster-component`、`version=2`、`asset` 图片数据、`part` 部件参数。整体文件：`schema=monster-assembly`、`version=2`、`assets` 素材库、`parts` 组合、`log` 操作记录。v2 增加 parentId、heightScale、portNames、portTypes。图片以 Data URL 内嵌；导入非图片 URL、未知版本、引用丢失、循环或数值越界会拒绝。

兼容读取 v1：旧唯一躯干成为根，其余部件迁移到该躯干，纵向比例补为 1，旧接口名称和类型按键推定。继续使用原缓存键以保留组合；无法转换的缓存会尝试另存 recovery 备份后载入默认模板。新版一律输出 v2，旧平台不兼容读取。组件文件解除外部父引用、保留世界位置，导入后分配新标识，再自动挂到所选躯干。

新增、替换、编辑、拖动、导入和导出等操作记录到浏览器及整体文件，最多保留 500 条；撤销与重做沿用状态快照，不是不可篡改审计。代码构建留痕则由本文件、CHANGELOG 和平台源文件共同承担。更改保存结构时增加格式版本，并给出旧版本迁移或明确拒绝提示。

## 验证与边界

初版支持 PNG、JPG、WebP 导入；示例部件为程序绘制的 SVG 占位图。没有上传接口或外部库请求，不执行导入 JSON 中的脚本。导出的 PNG 是静态图，不能证明物理连接、关节强度或运动稳定性。

测试应覆盖五类组合、替换长宽比不同的图片、修改接口后跟随、正反翻转、不同层级遮挡、组件和整体文件往返、透明 PNG 以及失败导入不破坏当前组合。自动保存超出浏览器容量时会提示导出备份。移动端可以浏览和调整，但主工作场景为桌面宽屏。

新版测试命令：`node tests/test_dynamic.cjs app.js`。目前自动测试覆盖三模板、多躯干跟随、独立肢体数量、动态接口、删点原地脱离、循环拒绝、v1 迁移、v2 导入导出和撤销重做。文件导入回调的隔离测试不等于真实浏览器文件选择往返；该项仍需团队用实际素材验收。
