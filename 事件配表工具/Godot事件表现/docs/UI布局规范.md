# 探索与事件 UI 格式原型

## 基础信息

- 界面 ID：`UI_MAIN_EVENT_EXPLORATION`。
- 分类与类型：主界面 HUD + 事件 overlay + 说明 popup。
- 入口：独立工程主场景；事件入口为底部“进入图书馆”。
- 父界面：探索示意；不依赖主游戏工程。
- 原型截图：`tests/00_shell.png`、`02_choices.png`、`02b_reward_preview.png`、`03_reward.png`、`05_glossary.png`。
- 参考来源：用户提供的 8 张“多少兄弟”截图。只归纳图中可见排版，不推定该游戏内部实现。

```text
┌──────────────┬──────────────────────────────────────────┐
│ 队伍数量     │ 地区 / 路线进度                日期 / 资源 │
│ 单位卡       ├──────────────────────────────────────────┤
│ 名称与数量   │ 场景区域 / 当前事件窗口                   │
│ 属性行       │ 标题、正文记录                            │
│ 词条说明     │ 选择卡：标题 → 说明 → 标签 → 操作         │
│              │ 奖励卡：解锁内容 | 资源奖励                │
│              ├──────────────────────────────────────────┤
│              │ 当前地点 / 提示              主操作按钮   │
└──────────────┴──────────────────────────────────────────┘
                说明浮层独立位于事件之上，不切换底层步骤
```

## 设计目标

把队伍与资源放在固定区域，让玩家始终知道当前拥有的东西；把地点、剧情、选择和领奖放在主要阅读区域，让每个阶段有清晰的主操作。借用参考截图的分组、对齐、卡片比较和层级关系，同时保留已经确认的逐句追加与上下文回看，避免为查看说明而丢失当前剧情位置。

|---|---|---|

## 功能说明

1. 常驻分区【必须/MUST】。
   - 当/WHEN：进入探索原型。
   - 则/THEN：左侧显示队伍，顶部显示路线/资源，中央显示地点，底部显示操作。
   - 且/AND：演示数字不参与真实战斗计算。
2. 滚动对话【必须/MUST】。
   - 当/WHEN：点击继续。
   - 则/THEN：在现有记录末尾追加一个节点，并滚到最新。
   - 且/AND：回看和“回到最新”只改变阅读位置，不推进剧情。
3. 双列分支【必须/MUST】。
   - 当/WHEN：出现选择节点。
   - 则/THEN：两列卡片显示标题、说明、标签、操作；第三项起另起一行。
   - 且/AND：继续按钮禁用；选择后移除旧按钮，追加玩家选择和对应分支首句。
4. 奖励分区与确认【必须/MUST】。
   - 当/WHEN：到达手动奖励节点。
   - 则/THEN：左侧展示解锁内容，右侧展示资源，底部主操作为“领取奖励”。
   - 且/AND：预览不发奖；点击后等待宿主确认；成功才出现“返回探索”。关闭不重复发奖。
5. 解释层级【必须/MUST】。
   - 当/WHEN：悬停带说明的内容。
   - 则/THEN：显示紧邻该内容、限制在窗口内的小面板，移开即收起。
   - 当/WHEN：点击词条或说明入口。
   - 则/THEN：显示独立说明窗口，关闭或 ESC 返回原步骤。
   - 且/AND：说明窗口期间不得误点到底层的继续、选择或领取。
6. 风格替换【应该/SHOULD】。
   - 当/WHEN：后续确定正式美术。
   - 则/THEN：先替换共享样式与图标，保留分区与节点接口。

## 视觉规格

1280×720 横屏基准。侧栏约 23%，右侧为主区域。标题 29–39px，正文 21px，卡片标题 23px，辅助信息 14–17px。分组内间距 6–12px，主分组间距 12–16px。灰阶纯色与细线用于验证结构，非最终颜色/材质。

## 导航流程

探索 → 进入图书馆 → 逐句对话 → 两列选择 → 分支内容 → 奖励预览 → 点击领取 → 等待外部确认 → 原卡片更新为回执 → 返回探索。

说明浮层是旁路：打开 → 查看 → 关闭，剧情节点、奖励状态和阅读位置不变。失败回执仍停在等待状态，正式系统从外部修复并以同请求 ID 重试确认。

## 数据需求与边界

- 宿主负责数据快照、触发判定、奖励、存档；UI 只显示并发出意图。
- 节点接口保留；选择卡格式字段可选，奖励模式默认兼容自动发放。
- 路线、队伍与章节是演示数据，不意味着已实现地图或战斗系统。
- 仅保留本次事件记录，不提供永久历史库。
- 验收：两分支、旧自动奖励兼容、预览不发奖、重复回执不发奖、浮层和历史不推进、标题不随滚动移动。
