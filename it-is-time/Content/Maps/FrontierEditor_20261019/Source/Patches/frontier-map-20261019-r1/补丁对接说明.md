# 地图增量补丁 · Godot 安装与系统接入

适用原包：`地图编辑器系统合并完整交接包_20261019.zip`（2,414,757,252字节，约2.4GB）。本补丁只携带原大包之后发生变化的文件与新增源码/素材；原高清底图分块与已交付美术从大包读取，位置和原始分辨率不变。

## 安装

1. 将原大包和本补丁分别完整解压到两个文件夹。关闭目标大包目录中正在运行的编辑器和游戏，避免保存操作与安装同时发生。
2. 在 **Godot 4.7.2** 项目管理器导入本补丁根目录 `project.godot`，按F5运行安装器。无需.NET、Python或第三方插件。
3. 选择原大包的解压根目录，应包含 `project` 和 `文件清单_SHA256.json`。依次点击“检查补丁”“备份并应用”。选择其中的project子目录也会向上定位。
4. 安装完成后，点击“打开大地图Godot工程”或“打开41张战场Godot工程”，在新编辑器按F5。无需再生成素材。浏览器编辑器继续使用大包原有 `启动本包编辑器.cmd` 入口；浏览器若保留旧页面，保存/备份个人编辑后重新打开。

请保留大包的原目录结构。补丁不能单独作为完整游戏运行。界面会核对大包版本、待替换文件与素材依赖；如同事改过待替换文件，将列出冲突并停止整个安装，应先比较合并后再重新生成合适补丁，不要盲目覆盖。重复安装已是本版的文件不会再次写入。

## 备份、回滚和校验

应用前备份位于大包 `补丁备份/<补丁编号_时间>/files`，回滚凭据为同目录 `receipt.json`。重新打开安装器，点击“选择凭据回滚”选择该文件即可。回滚会先核对全部文件；如安装后继续编辑过受影响文件，停止回滚以保留新进度。未改动文件原字节恢复，补丁新增文件删除，备份仍保留。安装失败会尝试自动恢复并报告结果。

原始 `文件清单_SHA256.json` 保留为版本标识；本轮完整文件清单为 `补丁后文件清单_SHA256.json`。更新后的 `校验交付包.py` 自动读取后者，需Python3；运行可验证全部交接文件，不统计后续缓存、截图和个人存档。后续修改布局后校验报告变化属于正常现象，需重新导出快照和清单。

补丁 `manifest.json` 逐项记录原/新SHA256，`required` 记录复用依赖，`payload` 为实际文件。仅应用清单内的文件，无批量删除操作。原2.4GB ZIP无需改写。

## 本轮保存的内容

- 10877个蜂窝格、631个点位、502条大地图素材记录、41张战场；权威数据、浏览器离线镜像、事件索引、逐场接入配置同步。
- 保存用户最新山体图层调整及道路/事件布局。山体支持整段删除和Ctrl+Z，美术透明轮廓生成阻挡；独立墙体和宽通路保留。
- 山体近侧岩面完整呈现，视线遮挡从山体后方出现。630视野外的岩面隐藏；细像素迷雾、柔边过渡、后缘压盖与山石间暗缝衔接保留。城镇和召唤小屋有扩大柔边地面衬底。
- 只补全召唤小屋左上指定岩石，补画为独立底层PNG，原山石链条原图未变。出生点与初始630视野跟随召唤小屋，保留原先开阔的引导形状。
- 全41张战场左右水平部署；双方内部阵型、人数及逻辑保持，避开障碍和地面效果。两张无敌方配置的历史模板仅预留敌方中心。
- 树、草、石、蛛网等相对地面默认抬起60°；泥潭、深坑与地表贴片保持贴地。14处画风不一致的旧Demo装饰已置换为已有素材。战场素材不加包边。
- 原高清底图48分块、树木85%版本、图标与事件内容沿用现有保存状态；本轮没有再次重绘/压缩整套美术。

## 接入文件与字段

权威编辑源：`project/frontier_toolkit/editor/hex/Data/Maps/hex_layout.json`、`hex_battles.json`。`Tools/hex-planner/layout.json`、`battles.json`、`events.json`为离线镜像。`数据导出`全部派生索引及41份 `逐场接入配置/*.battlelevel.json` 已从当前权威源重新生成，不能反向覆盖权威源。

大地图新增/扩展：

| 字段或源码 | 接入规则 |
| --- | --- |
| `spawn_site_id` / `spawn_site_anchor` | 绑定召唤小屋ID及相对于美术尺寸的归一化落点；用编辑器模型同步计算实际spawn，移动/缩放时一同更新，视野半径仍为630 |
| 山体 `terrain.boundary` | 保存美术实际透明轮廓及关联素材状态；替换美术后重新吸附，避免沿用旧边界 |
| `visual.layers` | 指定岩石补全底层，按原定位在山体主体后绘制；不能只渲染主PNG而丢弃补全部分 |
| `Tools/mountain-boundary.js`、`mountain-editor.js`、`mountain_outline.py` | 透明轮廓、删减/撤销、原生预览约束生成；沿用现有单位和坐标，不重新缩放整图 |
| `GodotPreview/MapSight.gd`、`CurrentMapPreview.gd` | 逻辑视线与岩面显示范围分开；近侧阻挡保持，岩面仍受半径裁切；后缘薄雾不裁坏岩石原图 |
| `MapPresentation.gd` 的 `ground_patch` | 可选enabled、size、color、opacity、asset，用于城镇/小屋柔边底座，供后续美术置换 |

战场新增/扩展：

| 字段 | 接入规则 |
| --- | --- |
| `map.deployment_layout` | version、axis=x、center_z、friendly_center、enemy_center、enemy_reserved，实际部署仍读对象坐标 |
| `map.presentation` | camera_pitch_degrees=-50、scenery_tilt_degrees=60，摄像机及美术姿态独立 |
| `object.visual.surface_mode` | auto / tilted / ground；按要素自动分类或单独指定 |
| `object.visual.tilt_degrees` | 相对地面0～90°；不是摄像机俯角 |

共享原生实现 `project/frontier_toolkit/editor/godot/battle_visual_pose.gd`：正式系统创建Sprite3D、父对象进入场景树后调用 `BattleVisualPose.apply(sprite, object_node, object_data, 60)`，Sprite3D.pixel_size=1。它补偿作者的缩放与旋转，固定图片底部的地面X/Z接触点；不能以倾斜后的图片重算碰撞/效果区。原 `battle_preview.gd` 适配器已调用共享实现。

同事已经导出的旧静态战场不会由覆盖JSON自动更新；请用本轮 `battle-model.js` 编译或使用更新的41份接入配置重建节点，并将共享姿态函数接入正式美术创建步骤。敌我彩色标记仅供部署核对，具体怪物角色、AI、回合与奖励由正式战斗系统创建。

事件条件、对话内容、触发入口、顺序和回调仍见同目录 `完整系统对接文档.md/.html`、`数据导出/事件入口绑定.json`、`事件参数与待绑定.json`、`事件触发请求示例.json`。本补丁同步事件快照及请求派生文件；不会虚构未接入的事件执行模块。统一存档、出战检查、遭遇战回调和奖励结果继续按原完整文档对接。

## 预览与再生成

两套Godot工程均为当前保存进度的原生表现验证：大地图可移动、缩放、查看城镇及F2全图审阅；战场可选择41张地图、比较45/60/75°。二者不写游戏进度，不执行事件、破坏持久化或真实战斗，不能当作完整游戏入口。两工程使用相对路径直接加载大包原PNG/SVG，未降清晰度；本补丁仅新增单块岩石补全PNG。

布局之后再编辑保存，需要重新生成相应预览快照。大地图运行 `GodotPreview/Start-CurrentMapPreview.ps1 -GodotPath <godot.exe> -PythonPath <python.exe>`；战场使用 `GodotBattlePreview/Start-BattlePreview.ps1` 同样参数。输出默认在各自 `generated-preview`。Python大地图生成依赖Pillow、NumPy、SciPy、Shapely（支持约束Delaunay三角剖分）；战场仅标准库。初次安装附带匹配的scene.json/battle_scene.json，完全无需Python。

快照生成器校验权威布局SHA256，过期会报错并拒绝加载，避免误看旧版本。自动生成数据不作为另一份地图编辑源；移动工程时保持相对目录结构。正式表现模块可复用这些源码，但须接入自己的存档、角色和事件系统。

## 本补丁不包含的内容

浏览器撤销历史、个人游戏进度、编辑器缓存、Godot导入缓存、机器专用路径与原大包未改动的大体积美术不重复打包。本次不覆盖其他系统的C#源码。原完整文档中的历史缺件和待绑定项仍按原说明处理。
