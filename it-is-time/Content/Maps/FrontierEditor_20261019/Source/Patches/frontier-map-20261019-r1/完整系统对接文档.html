3. 大地图蜂窝与坐标

大地图使用平顶六边形，世界矩形起点 [70,100]、大小 [27900,16350]，单格横向顶点跨度 255。轴坐标 (q,r) 不是贴图像素。令 R=255/2，格心为：

x = origin.x + 1.5 × R × q
y = origin.y + √3 × R × (r + q/2)
origin = [70,100]

相邻轴坐标偏移为 (1,0)、(0,1)、(-1,1)、(-1,0)、(0,-1)、(1,-1)；相邻格心距离约 220.8365 世界单位。请直接复用 model.js 的 center/axial/corners 或 Python hex_layout.center，反算格子要做 cube rounding，不能分别取整后直接使用。

底图贴在 background.position/size 指定的世界矩形；高清图像像素通过此矩形转换。38400×22500 是母版配准画布，并不表示每张生成分块都有同样的原生像素密度。图标放大和怪兽尺寸不改变格子大小、坐标或触发范围。

独立石块与破坏流程

27 块可破坏石头使用各自形状与透明素材。site.destruction.cells 和 cell.obstacle_ids 双向绑定；共享格需所有 owner 被破坏才开放。灰石与黑石按图 8 原位美术维护，位置、外观与逻辑区块分别记录。换图不能把所有石块换成同一张，也不能按矩形粗切代替真实轮廓。

  • 调用 HexContentModel.destructionRequest(doc, obstacleId) 读取稳定 ID、素材位置、格子列表、持有怪物条件和 cost={unit:"walk_steps",amount:3,clock_owner:"host"}。
  • 正式宿主验证持有怪物、相邻可达、当前未破坏，再使用程序已有的行走计时计算 3 格耗时。试玩单格默认为 0.6 秒，不能将 1.8 秒硬编码为正式规则。
  • 动作成功后调用 commitDestruction(doc,id,destroyedSet)，隐藏 remove_visual_ids、移除本块碰撞，按 opened_cells/blocked_cells 更新导航。取消、失败或条件失效不提前隐藏。
  • 保存 destroyed_obstacle_ids；读档用 restoreDestruction 恢复。重复提交返回 already_committed，不能重复消耗或清空仍受其他石头/永久地形约束的格子。

4. 战场工作集与营地衔接

大地图以 site.battle_map_id 指向 hex_battles.maps[].id，enemy_config_id 对应战场 encounter.enemy_config_id，独立战场回指 encounter.source_site_id。不要通过名称、下拉顺序、图标或怪物中文名猜关联。当前逐点配对及完整敌军对象见 数据导出/战斗点与战场关联.json。

战场是独立的小尺度坐标空间：objects[].position=[X,Z]，height 为高度；大地图世界坐标不能直接写入战场。maps[].hex_grid.cell_width 常用 2.2，以每张实际配置为准；orientation 可能为 flat 或 pointy，后者使用模型中的 30° 旋转。maps[].radius 是战场边界尺度，与大地图遭遇半径无换算关系。

数据导出/逐场接入配置/*.battlelevel.json 采用编辑器现有“导出接入配置”格式：format=frontier-battle-level, version=1, map, assets, art_bindings, catalogs。由 HexBattleModel.compileMap 将多格占地展开成真实六边形多边形，保留 semantic_group；不能将占地改成包围矩形。它是接入数据，不是完整可执行战斗。旧连续编辑器的 project.json/level.json 与当前 hex 工作集是不同格式；旧 Godot 转换器接入前应逐类型确认支持范围。

遭遇前出战与返回流程

正式流程应为：地图遭遇/主动挑战 → 固定本次来源点和返回位置 → 检查出战怪物 → 没有出战时打开出战页面 → 玩家确认后复查队伍 → 加载对应战场 → 战斗结果提交成功 → 结算页面 → 关闭结算后回到原地图位置，恢复迷雾与破坏状态。取消编队、加载失败或退出均不能当作胜利。19/20 号观战事件使用两方 AI，不能套用“玩家无队伍就拒绝观战”。

这段是系统合并需要落实的流程要求；浏览器营地入口和请求输出不表示 UI/主工程已完成真实战斗链路。工具箱已有 docs/battle_integration/ 的 request/result schema、代码审计与实施计划，完整原件一并保留；其中新协调器类和部分 DTO 为设计约定，接入时按实际实现核对，避免保留 FakeBattleAdapter 和正式入口同时响应。

数值参数与未绑定内容

唯一数值编辑入口是 event.runtime_bindings.parameters；parameter_specs 记录 label/type/unit/min/max/allow_unconfigured。编辑器“事件库 → 接入参数 JSON → 保存接入参数到布局 → 保存布局”。不要通过改规格、分支键、事件 ID 来调数值。14/15/20 的旧 trigger_policy 兼容字段在请求时由 parameter_bindings 投影，不再维护第二份数值表。

null 表示未配置，不是 0、免费、条件通过或随机生成。未绑定的敌军、奇物、符文、天气、概率和交易结果仍应阻止相应业务执行并提示缺项。数据导出/事件参数与待绑定.json 完整保留每条参数及规格；生成的请求只是配置载荷，不承诺宿主已执行这些数值。

二 地图入口如何接到现有UI

接入路线由正式宿主统一编排。事件窗只接显示数据和提交操作；魔力、怪物、阶段和奖励账本仍由正式GameSession及其业务服务维护。

顺序动作执行要求
1点击并抵达地图先检查可达、距离和开放条件；点击图标本身不算事件完成。
2读取入口绑定读取event_id及stage_id或entry_role；同时读取当前正式进度。城市先筛选当前可用的子入口。
3打开事件窗EventPanel的Description放当前正文，Commands放当前选项。说话人可随正文分段；策划注释留在配置。
4提交选择发送事件、会话、阶段及稳定branch_key；宿主再次检查余额、队伍和路线状态，防止过期按钮执行。
5等待外部结果战斗、交易、献祭和奖励提交期间锁定重复操作；切到其他页面时保存待处理状态。
6显示结果读取真实成功或失败回执后，显示战后文案或下一阶段。关闭窗口只结束本次显示。
7刷新与返回存档成功后刷新A1资源、待办及地图入口；战斗先结算，确认后大地图下拉，再恢复探索。

4. 节点、分支与外部等待

5. 事务、奖励与持久化

展示组件只发出意图，正式宿主拥有魔力、怪物、天气、事件进度和存档。不得让原型与正式服务各扣一次、各保存一份。推荐的语义事务为：校验→生成/复用请求→锁定结果→提交消耗、奖励、状态及去重账本→成功回执→刷新UI。具体实现由宿主决定，不在文案中绑定函数名。

  • 购买引擎：扣100魔力、扩一圈、购买标记属于同次事务；余额不足、满级、保存失败不得只完成一半。
  • 献祭：选择实际怪物实例→显示将消耗的对象→不可逆确认→复核实例可用及条件→回收、奖励及阶段进度按同一请求持久提交。下一要求必须等本阶段奖励成功后才显示；若已消费待发奖，重试不得再次扣怪。天气效果未定，不擅自写入默认天气。取消不回收。不能因为一个怪物满足多个标签就重复消费同一实例。
  • 怪物奖励：谁会赢？的强化双头甲狼/魔眼拱兽必须有实际预设和实例ID；库存或队伍容量不足时按正式安置规则处理，不能静默丢弃或直接插入满员出战队伍。
