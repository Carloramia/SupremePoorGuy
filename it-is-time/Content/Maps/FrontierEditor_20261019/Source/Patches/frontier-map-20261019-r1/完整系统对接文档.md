## 3. 大地图蜂窝与坐标

大地图使用平顶六边形，世界矩形起点 `[70,100]`、大小 `[27900,16350]`，单格横向顶点跨度 `255`。轴坐标 `(q,r)` 不是贴图像素。令 `R=255/2`，格心为：

```text
x = origin.x + 1.5 × R × q
y = origin.y + √3 × R × (r + q/2)
origin = [70,100]
```

相邻轴坐标偏移为 `(1,0)、(0,1)、(-1,1)、(-1,0)、(0,-1)、(1,-1)`；相邻格心距离约 `220.8365` 世界单位。请直接复用 `model.js` 的 `center/axial/corners` 或 Python `hex_layout.center`，反算格子要做 cube rounding，不能分别取整后直接使用。

底图贴在 `background.position/size` 指定的世界矩形；高清图像像素通过此矩形转换。38400×22500 是母版配准画布，并不表示每张生成分块都有同样的原生像素密度。图标放大和怪兽尺寸不改变格子大小、坐标或触发范围。

| 字段 | 含义 |
| --- | --- |
| `cells[].q/r/region` | 格子稳定坐标与六种区域：forest、spider、sparse、grass、pit、desert |
| `cells[].feature` | wall、river、breakable、bridge；空值为普通地形 |
| `cells[].control` | allowed 可通过；outside 边缘禁止；breakable 橙色控制区，破坏条件满足后开放 |
| `condition_ref/control_condition_ref` | 外部条件引用，需宿主解析，空值不构造额外业务 |
| `event_id/event_trigger/event_links` | 单事件或共享事件入口；格子入口和点位入口分别保存 |
| `sites[].id/kind/position` | 稳定点位身份、类型与世界坐标；命名变化不更换 ID |
| `sites[].radius` | 大地图交互/遭遇半径；独立于 visual.width 与战场 radius |
| `roads[].points/width` | 世界坐标道路折线；保存现有节点，不重新自动识别或平滑 |
| `crossings[].points/width` | 跨河桥梁通道；道路外观不赋予任意渡河能力 |

黑色 wall 是阻挡及视野遮挡山体；只有完全位于 pit 区域、连通块不超过 7 格的散点 wall 按深坑解释，详见 `model.js/hex_layout.py` 的 `wallKinds/wall_kinds`。左下长墙保留阻挡逻辑，背景已画墙，不能再自动补一串黑石。地图外、outside、永久 wall/river 与未破坏石障叠加约束，不能用美术透明度推断通行。

出生点 `[3220,11372]`，位于召唤小屋附近；初始视野半径 `630`，`fog.enabled=true`，`preserve_exploration=true`。宿主需要按现有山体遮挡语义计算实时视野并保存探索记录；编辑器显示全图不等于取消战争迷雾。编辑源地图与玩家位置、迷雾、战斗完成、破坏列表分开保存，不能将同事预览中的试玩进度作为新游戏存档。

### 独立石块与破坏流程

27 块可破坏石头使用各自形状与透明素材。`site.destruction.cells` 和 `cell.obstacle_ids` 双向绑定；共享格需所有 owner 被破坏才开放。灰石与黑石按图 8 原位美术维护，位置、外观与逻辑区块分别记录。换图不能把所有石块换成同一张，也不能按矩形粗切代替真实轮廓。

1. 调用 `HexContentModel.destructionRequest(doc, obstacleId)` 读取稳定 ID、素材位置、格子列表、持有怪物条件和 `cost={unit:"walk_steps",amount:3,clock_owner:"host"}`。
2. 正式宿主验证持有怪物、相邻可达、当前未破坏，再使用程序已有的行走计时计算 3 格耗时。试玩单格默认为 0.6 秒，不能将 1.8 秒硬编码为正式规则。
3. 动作成功后调用 `commitDestruction(doc,id,destroyedSet)`，隐藏 `remove_visual_ids`、移除本块碰撞，按 `opened_cells/blocked_cells` 更新导航。取消、失败或条件失效不提前隐藏。
4. 保存 `destroyed_obstacle_ids`；读档用 `restoreDestruction` 恢复。重复提交返回 `already_committed`，不能重复消耗或清空仍受其他石头/永久地形约束的格子。

## 4. 战场工作集与营地衔接

大地图以 `site.battle_map_id` 指向 `hex_battles.maps[].id`，`enemy_config_id` 对应战场 `encounter.enemy_config_id`，独立战场回指 `encounter.source_site_id`。不要通过名称、下拉顺序、图标或怪物中文名猜关联。当前逐点配对及完整敌军对象见 `数据导出/战斗点与战场关联.json`。

战场是独立的小尺度坐标空间：`objects[].position=[X,Z]`，`height` 为高度；大地图世界坐标不能直接写入战场。`maps[].hex_grid.cell_width` 常用 2.2，以每张实际配置为准；`orientation` 可能为 flat 或 pointy，后者使用模型中的 30° 旋转。`maps[].radius` 是战场边界尺度，与大地图遭遇半径无换算关系。

| 配置 | 接入用途 |
| --- | --- |
| `hex_cells[].ground` | plain/grass/soil/stone/sand/water 地面涂色，只表示外观，不自动加移速或伤害 |
| `hex_cells[].control` | allowed/outside/breakable 控制层；编译时转成对应多边形对象 |
| `wall` | 边界空气墙厚度、高度、层及阻挡说明；围边装饰不代替物理边界 |
| `background_blur/edge_feather/background_color` | 原有场外光晕表现配置；不能因更换场内背景丢弃 |
| `objects[].visual` | 素材、视觉尺寸、透明度、显隐、层级；`visible=false` 的旧围边作为参考保留 |
| `collision/region/click_area` | 实际碰撞、效果范围、交互范围，与图像大小相互独立 |
| `linked_collision_id/visual_id` | 美术对象与独立碰撞的双向关联，移动时同步检查 |
| `deployment.slots/facing` | 己方部署槽与朝向，均需正式队伍/部署适配 |
| `enemy` 对象 | monster_config_id、definition_id、monster_species、monster_type、monster_size、grouped、count、team_group、位置和朝向 |
| `post_battle` | 战后事件、召唤、升级等语义引用；需正式宿主完成条件判断与业务执行 |
| `effect_ref/condition_ref` | 留给效果/规则系统的 ID，缺项不得静默视为已配置 |

常规战斗阵容的数量以当前战场 `type=enemy` 的对象 count 求和，不从图标、敌群摘要或旧事件备注反推。形态分蛇形、人形、兽形、蜘蛛形、飞行类，尺寸 tiny/small/medium/large/huge 单独设置；形态不决定体型、群体属性和强度。I 级默认 4—5，II 普通 6—7，II 高段 8，III 常规 9—10，02 和 08 保留故事单体，羊主为主怪加弓手共 4。具体以本包实际对象为准。复合点只允许 II 高段/III、最多两组；蜘蛛只在 spider 区域；III 关闭自动遭遇，保留主动挑战。

大地图“编辑此战场”打开关联场景；在战场保存后，返回大地图刷新敌群摘要。`HexContentModel.battleRequest(doc,site,battle)` 输出 `frontier.battle.request`，其中 `readiness=host_roster_binding_required`；`definition_id=null` 的物种仍需程序接正式资源，不能用其他物种凑数。所有战场已保留各自环境布局、围边、光晕、部署和战后入口，但真实 AI、角色模型、伤亡与奖励不由地编实现。

`数据导出/逐场接入配置/*.battlelevel.json` 采用编辑器现有“导出接入配置”格式：`format=frontier-battle-level, version=1, map, assets, art_bindings, catalogs`。由 `HexBattleModel.compileMap` 将多格占地展开成真实六边形多边形，保留 semantic_group；不能将占地改成包围矩形。它是接入数据，不是完整可执行战斗。旧连续编辑器的 project.json/level.json 与当前 hex 工作集是不同格式；旧 Godot 转换器接入前应逐类型确认支持范围。

### 遭遇前出战与返回流程

正式流程应为：地图遭遇/主动挑战 → 固定本次来源点和返回位置 → 检查出战怪物 → 没有出战时打开出战页面 → 玩家确认后复查队伍 → 加载对应战场 → 战斗结果提交成功 → 结算页面 → 关闭结算后回到原地图位置，恢复迷雾与破坏状态。取消编队、加载失败或退出均不能当作胜利。19/20 号观战事件使用两方 AI，不能套用“玩家无队伍就拒绝观战”。

这段是系统合并需要落实的流程要求；浏览器营地入口和请求输出不表示 UI/主工程已完成真实战斗链路。工具箱已有 `docs/battle_integration/` 的 request/result schema、代码审计与实施计划，完整原件一并保留；其中新协调器类和部分 DTO 为设计约定，接入时按实际实现核对，避免保留 FakeBattleAdapter 和正式入口同时响应。

### 已存在的请求接口

```javascript
const CM = window.HexContentModel;
const requests = CM.requestsForIcon(doc, "layout_foster_town", {
  mode: "host_integration" // 接入方上下文；不是正式存档
});
// 单个格子或点位可用 CM.request(doc, target, context)
// 参数读取：CM.parameter(doc, eventId, key)，未配置会抛错
```

请求字段包括：`type="frontier.event.request"`、`version=1`、`event_id`、`source_id`、`trigger_mode`、`entry_enabled`、`stage_id`、`once`、`readiness`、`unresolved`、`runtime_bindings`、`context`。`requestsForIcon` 另含 `entry_role/inherit_click_area`。启用入口与业务可发布是不同状态；当前 `pending_binding` 应保留，不能因为已经有坐标就改为 ready。

触发模式枚举为 `interact、enter_range、on_discover、on_game_start、on_game_time、battle_won、dialogue_complete`。编辑器试玩通过当前 world iframe 的 `window.dispatchEvent(new CustomEvent('frontier:event-request',{detail:request}))` 发出；宿主需在该窗口上下文订阅或新增显式桥接。此 CustomEvent 不自动穿过 iframe，不能只在外层 shell 监听后就认为已接收。普通接入程序也可以直接调用内容模型生成请求。

宿主接收后负责：条件与阶段筛选 → 持久请求去重 → 展示本阶段对白与真实选项 → 外部等待/战斗/交易 → 提交消耗、奖励、任务状态 → 成功回执后更新 UI。`EventPanel.tscn` 仅提供正文与固定选项布局，正文中的【选项】、自然语言条件和 `branches` 说明不会自动转成执行图。当前事件 `execution_graph=null` 的条目必须由事件系统负责人补齐节点，不可顺播全文后直接发所有奖励。

### 数值参数与未绑定内容

唯一数值编辑入口是 `event.runtime_bindings.parameters`；`parameter_specs` 记录 label/type/unit/min/max/allow_unconfigured。编辑器“事件库 → 接入参数 JSON → 保存接入参数到布局 → 保存布局”。不要通过改规格、分支键、事件 ID 来调数值。14/15/20 的旧 trigger_policy 兼容字段在请求时由 parameter_bindings 投影，不再维护第二份数值表。

`null` 表示未配置，不是 0、免费、条件通过或随机生成。未绑定的敌军、奇物、符文、天气、概率和交易结果仍应阻止相应业务执行并提示缺项。`数据导出/事件参数与待绑定.json` 完整保留每条参数及规格；生成的请求只是配置载荷，不承诺宿主已执行这些数值。

## 7. 保存协议、系统合并顺序与验收

本地服务 `Tools/serve_hex_planner.py` 只监听 127.0.0.1。GET `/api/layout`、`/api/battles` 返回当前 JSON 和 ETag；ETag 是原始文件字节 SHA256。POST 同路径提交 JSON，携带当前 `If-Match` 与同源 Origin；30 MB 请求上限。保存前进行结构、范围、来源、参数及双向绑定校验；成功原子替换并备份。冲突返回 409，导出草稿后人工按稳定 ID 合并，不能用旧快照强行覆盖。

`source_sha256/source_maps` 标记原始来源，服务会限制不兼容来源与历史战场丢失。范围与 grid 也是兼容条件。合并新项目时先保留数据来源，再设计显式迁移；不要为绕过保存校验随便修改这些字段。编辑器撤销栈与视角属于临时浏览器状态，导出的是已保存工作内容，不是可重放的整个编辑操作历史。

建议按以下顺序接入：

1. **资源与只读布局**：导入当前 map/battles，建立稳定 ID 和资源注册表映射，先核对图 8 位置、85% 树木、高清底图、围边和光晕。
2. **通行与雾**：按格子和桥梁建立导航/视野遮挡；实现独立石障破坏与读档，检查永久约束及重叠 owner。
3. **队伍与战斗**：接入真实 monster instance、出战前跳转、独立战场加载、敌群预设、战斗生命周期与可靠返回。先禁用旧测试战斗入口。

| interaction_id | NPC、货车、祭坛等实际入口 | 将正文中的NPC称呼当作正式资源ID |
| 开放/触发条件 | 谁、何时、在哪种状态可进入 | 空条件或待定解释为自动通过 |
| stage_id | 同一事件内阶段，例如等待回城 | 把每个阶段算作一个新事件 |
| branch_key | 选项稳定键，总表第一列 | 用按钮排序或完整中文台词当存档键 |
| 展示正文 | 旁白、说话人、笔记与选项标签 | 把括号里的奖励/判定注释当对白 |
| battle_map_id / enemy_config_id | 战斗场景与真实敌方预设 | 缺预设时替换敌人、传空敌军自动胜利 |
| reward/item/rune/preset ID | 真实资源标识 | “奇物”“符文”当作任意默认奖励 |
| once_key / request_id | 奖励去重键与操作请求关联键 | 每次重开面板生成新领奖键 |
| publish_status | 草稿→待绑定→联调→可发布 | 待定字段尚未补齐就标可发布 |

总表的`active / complete / battle_pending`等状态词和分支键是策划约定，并非新注册的宿主字段或已实现API。正式字段需要系统负责人映射。读取怪物的攻击力、体型、皮毛、飞行与手足组件都用正式数据，不从立绘、中文名字或显示尺寸推断。

#### 4. 节点、分支与外部等待

每个执行节点应有稳定`node_id`、类型、正文/说话人、下一节点；选项另有分支键、可见条件、可选条件、不可选提示与去向。正文、选项、条件、动作必须分离。节点读完或窗口关闭只结束播放，不能自动完成事件。07号的归还明确由指定共用对话完成，不等待实际护送；18号只有当前阶段奖励成功，才开放下一阶段。

- **纯对话**：按正文顺序展示，确认结束；有奖励时等待提交成功再完成。没有写明玩家选择的台词不扩展成分支。
- **战斗**：玩家选择/已确认遭遇→按模式校验阵容（玩家战斗校验玩家队伍与敌军；观战只校验两方AI阵容）→保存本次请求→进入战斗→等待对应结果→胜利后展示后文、结算。失败、加载失败、取消和退出均不进入胜利路线。
- **跨地点任务**：接取→持久保存阶段→离开窗口→在目标城市/入口按阶段路由→交付。不得把“以后帮你问”立即接到领奖节点。
- **能力判定**：确认时重读正式持有怪物字段；10号包括仓库和出战怪物，任意单只攻击力高于阈值即可，不要求先入队。失败保留未完成，不凭全队加总代替单只攻击力。
- **互斥路线**：富含矿物质、谁会赢？在成功终局后锁定，其他终局不可再次领取。过分敬业更早在接取回城路线时锁定，之后不能改选直接解决，离开或读档不解除锁定。
- **汇合奖励**：外行魔法师的两种回答共享同一奖励节点，不能两份各发一次。
- **离开**：没有额外说明时不扣费、不领奖、不完成、不抹除已发现/已接取阶段。一次性与完成后隐藏是本次默认接入建议，原稿未定的重复规则仍可由作者调整；不要在未确认前将其作为正式发布规则。

同一事件有互斥选择时，选择确认与执行必须再次读取最新状态。连点、两个窗口或读档后重试不能同时完成两条路线。

#### 5. 事务、奖励与持久化

展示组件只发出意图，正式宿主拥有魔力、怪物、天气、事件进度和存档。不得让原型与正式服务各扣一次、各保存一份。推荐的语义事务为：校验→生成/复用请求→锁定结果→提交消耗、奖励、状态及去重账本→成功回执→刷新UI。具体实现由宿主决定，不在文案中绑定函数名。

一次性结果键可按`event_id:stage_id:result_id`映射到宿主账本；重复事件按持久`round_id`或`encounter_id`区分。操作重试复用原请求，不重新随机奖励或重复消耗。

- 购买引擎：扣100魔力、扩一圈、购买标记属于同次事务；余额不足、满级、保存失败不得只完成一半。
- 献祭：选择实际怪物实例→显示将消耗的对象→不可逆确认→复核实例可用及条件→回收、奖励及阶段进度按同一请求持久提交。下一要求必须等本阶段奖励成功后才显示；若已消费待发奖，重试不得再次扣怪。天气效果未定，不擅自写入默认天气。取消不回收。不能因为一个怪物满足多个标签就重复消费同一实例。
- 怪物奖励：谁会赢？的强化双头甲狼/魔眼拱兽必须有实际预设和实例ID；库存或队伍容量不足时按正式安置规则处理，不能静默丢弃或直接插入满员出战队伍。
- 结果回执：至少关联事件、阶段、分支、请求及战斗ID。旧战斗或重复回执不能推进当前另一分支。
- 随机行为：需要明确概率、候选池、抽取时机与持久结果；打开窗口、查看文本、读档重试不能擅自重掷。

#### 6. 显示与完成规则

待办只显示当前尚未完成且可行动的目标；完成记录不继续占用待办列表。一次性事件成功提交且无后续时隐藏对应事件图标。城市、图书馆等共享入口继续保留；只移除其中已完成的任务选项。

“已发现”“已阅读”“已接取”“战斗胜利”“已领取”“已完成”是不同状态。离开不等于失败，更不等于完成。有后续时切换到正确阶段入口；不可直接删除整条事件链。

战斗结束顺序遵守现有原型：先弹结算，玩家结束结算后再由整个大地图下拉遮挡小地图。事件正文继续使用现有纸质面板、安全标题留白、固定选项与原有字体，不为接入内容修改布局。战斗地点的简短概况沿用悬停显示，点击才执行确认后的入口逻辑。

#### 四条必须单独处理的时序

##### 石塔物品与狼群战斗

拾取确认 → 提交物品奖励并保存已领取 → 进入狼群战斗 → 接收胜利/失败。

物品阶段和战斗阶段使用不同的去重记录。战败、退出、战斗加载失败不能撤回已成功领取的物品。物品内容暂时搁置，正式配置缺失时不能随便发一个默认奇物。

##### 引擎购买后的4天

购买事务成功 → 保存购买游戏时间与到期时间 → 游戏时间达到或超过到期值 → 安排鬼魂出现 → 保存已触发记录。

跨日跳过和读档也必须检查到期。重新进地图、开书或加载存档不能重新开始4天倒计时。若当前正处于战斗或其他不可打断会话，保存已到期状态，待安全演出入口可用后出现，不再次计时或重复排队。

##### 献祭后逐次揭示要求

显示当前要求 → 校验并确认 → 提交本阶段献祭与奖励 → 收到持久化成功的奖励结果 → 显示下一要求。

- 玩家初次只能看第一次；第二、三次的文字、条件和可点选入口不能提前显示。策划总表保留三段，不代表运行时整段顺序播放。
- 第一阶段：恰好1只有皮毛怪物，不额外判断修长；第二阶段：恰好2只飞行怪物；第三阶段：恰好3只蛇类且无手无足怪物。
- 确认时重读库存及候选。每阶段扣除后，玩家持有总数至少剩1只；同一实例不能占两个名额，且遵守正式不可回收、占用和锁定规则。
- 只收到回收成功，不能揭示下一段。若已消费但奖励未成功，恢复同一待发奖请求，不再扣怪；若整个事务已回滚，则按同请求重试，不伪装成已经消费。
- 奖励失败、存档失败或恢复未完成请求时，仍停留在当前阶段；禁止以“没有填奖励”当作零奖励成功。
- 原稿的前两次临时血雨、第三次永久血雨仍作为内容描述保留；实际作用、范围、时长及覆盖待定。不要擅自调用默认天气效果。

##### 四次赌局与骑士离开

按已结算次数选择第1—4轮 → 校验手填双方配置 → 确认下注并锁定本轮 → 两方AI实际对战 → 匹配真实结果并结算 → 成功后次数加1。

| --- | --- | --- | --- |
| 1 | 10 | 20 | 10 |
| 2 | 20 | 40 | 20 |
| 3 | 50 | 100 | 50 |

返还2B已含本金，不能再另返B。双方阵容由策划手填，不是随机怪物池；缺配置不得以空阵容或临时抽怪开场。玩家不部署怪物，不能把普通玩家战斗的胜利标记当作所押一方获胜，也不能因玩家未编队就把AI中的一方判负。

胜负结算均计一次；第四次结算后保存事件永久结束，移除骑士及相关待办，重载不再出现。未下注离开不计次。失败具体支付、平局及中止后的账务仍待确认，不能自行结算或提前消耗一次次数。
