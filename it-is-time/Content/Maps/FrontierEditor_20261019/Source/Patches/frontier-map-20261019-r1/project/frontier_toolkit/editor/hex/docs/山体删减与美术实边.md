# 山体删减与美术实边

## 操作

1. 当前页面如有未保存修改，先按 **Ctrl+S**，再刷新编辑器载入新功能。
2. 切换到 **选择 / 移动**，点击山石本体；也可以在左上 **定位点位** 中选择“图8原位山体”。
3. 删除用 **Delete** 或右侧 **删除整组山体及关联阻挡**。**Ctrl+Z** 恢复，**Ctrl+S** 保存。每条图8山脉目前是一张完整素材，删除按组处理，不能直接点掉同一素材内部的单颗石头。
4. 选中山体后，在右侧 **山体编辑** 点击 **边界吸附山石实边**。也可点左侧 **全部山体吸附美术边缘**，一次处理所有山体。
5. 实边会以细线显示在山石外缘；拖动、旋转和修改图像宽度后，轮廓自动同步。更换素材时旧轮廓会清除，需要重新吸附。吸附和删减都进入同一套撤销记录。

“擦除图层”只清网格规则，不删除美术贴片。独立绘制的屏障仍是独立规则；删除一组山体时不会清掉其他山体的共享阻挡，也不会删除没有关联美术的背景墙。

## 边界口径

实边读取素材 PNG 的透明通道，阈值 96，识别分辨率最长边不超过 1024，简化误差约 1.25 个识别像素。接触阴影等低透明度部分不参与阻挡。轮廓保留凹口、石间开口、分离部分和孔洞，不使用凸包。误差与美术世界尺寸有关，一般为几个世界单位，远小于 255 单位的蜂窝格。

山体细缝使用黑色接缝底层压盖，并对约 36 世界单位以内的狭缝做闭合，避免漏底和漏光。宽的通路入口保留；可破坏石障不参与此处理。补缝不移动或重画山石图片。新生成边界保存 `seam_shadow: true`、`seam_width: 36`；旧边界在编辑器中重新点击“吸附”即可更新。Godot 预览会为旧山体自动生成对应补缝与遮挡。

编辑器视野、交互试玩通行及 Godot 当前地图预览共用保存后的轮廓。寻路除了检查格子中心，还检查相邻格的连线，避免跨过细窄山石。视野仍为 630，范围外的山石不能因边界吸附而出现。

吸附本身只写轮廓 metadata，不会移动、缩放、重画图片或擅自删除山体。是否应用哪一组由编辑者决定。保存后重新运行 Godot 预览启动脚本，生成与已保存布局一致的视觉约束。

## 系统合并字段

```json
{
  "terrain": {
    "kind": "mountain",
    "blocks_movement": true,
    "blocks_vision": true,
    "cells": ["16,44"],
    "boundary": {
      "version": 1,
      "mode": "art_alpha",
      "asset_id": "map8_exact_birth_curve",
      "asset_path": "assets/...png",
      "threshold": 96,
      "rings": [[[0.1, 0.2], [0.3, 0.2], [0.3, 0.5]]]
    }
  }
}
```

`rings` 是图片内归一化坐标，采用奇偶填充规则，末点隐式连接首点。先按 `visual.width`、素材宽高比及 `height_scale` 换算，减去图片锚点，再旋转和平移到 `site.position`。轮廓与当前素材 ID、路径必须匹配。

设置实边后，已由该山体完全拥有的旧 `mountain_ids` 蜂窝格仅作编辑关联和向旧版本回退的数据；支持实边的宿主必须用轮廓覆盖这些粗格的山体碰撞及 LOS。手工新绘的独立山体格标记 `mountain_manual_rule: true`，继续按蜂窝阻挡；共享格只在全部山体主人都支持实边时覆盖。其他控制层、河流、可破坏石障不受影响。

JavaScript 几何模块为 `Tools/hex-planner/mountain-boundary.js`，提供轮廓变换、点包含、线段遮挡和粗格覆盖判定。Godot 对应 `MapSight.art_surfaces`、`HexMapData.sight_occluders`、`HexMapData.blocked`、`HexMapData.crosses_art`。第三方宿主若只按旧 `cell.feature == wall` 判断，仍会看到粗格误差，需要接入上述新字段。

正式布局和已有交付压缩包不会因更新代码自动更改。新版编辑器中保存后，轮廓随布局 JSON 一起导出；原有历史交付包仍为原快照。
