地图与战场 · 蜂窝灰盒编辑器

用涂色与符号编排地形、障碍、效果和部署。战场沿用原编辑器的 X/Z 平面坐标及独立高度 Y；灰盒单块默认宽 2.2，可在场景设置中修改。13 个现有战场、549 个对象已导入，原坐标、围边组合、外部虚化和美术引用保留。

打开与切换

  1. 在 Godot 工程中运行 Tools/Start-HexPlanner.ps1，打开 http://127.0.0.1:8766/。
  2. 顶部切换“大地图灰盒”和“战斗场景”，快捷键 Alt+1 / Alt+2。两个编辑器保持打开，切换保留未保存修改、撤销记录、选择和视角。
  3. 大地图选中战斗点位，在属性中指定“战场模板”，点“编辑此战场”进入对应战场；点“返回大地图”回到原位置。
  4. 战场下拉菜单切换模板。每个战场有独立的视角和撤销记录；新建 / 复制战场后先保存，再在大地图点位下拉框选择它。

战场绘制

工具操作与规则
地面涂色选择地面颜色，单格 / 7 格 / 19 格笔刷拖动涂绘。浅水是地面标记，通行限制通过障碍或控制层配置。
障碍与陷阱固定、可破坏、可跨越、碰撞伤害、深坑、荆棘、泥潭、蛛网。一笔形成一个可选对象，效果沿蜂窝格占地；独立设置碰撞高度、坑深、作用对象、伤害、间隔、减速和控制时长。
己方部署区 / 槽位涂部署区时每格生成一个槽位。选中部署区后用“添加己方槽位”添加；右侧槽位列表为相对 X/Z 坐标，可删减。检查器会检查场内、区内、障碍、深坑、控制层和重复占位。
敌方点位点击放置，可拖动并设置朝向、怪物配置 ID、编队、数量。形态分蛇形、人形、兽形、蜘蛛形、飞行类；尺寸、群体与数量独立，不限制为三只。
战后事件配置事件 ID、条件、目标场景、点击范围和召唤 / 升级选项。
边缘控制独立涂色层：红色禁止进入，绿色允许区域，橙色破坏后可通行。橙色默认条件 has_monster；可选择蜂窝后填写其他条件和事件。绿色不会解除实体障碍和深坑。
环境与围边树丛、地表装饰、围边装饰和残骸用色块表示。与碰撞、效果层分开。原有美术 ID 和围边组合保存在工作集中。
擦除只擦除选定图层。历史对象被命中时删除整个对象，蜂窝对象只擦去命中的格子；可撤销。

选择对象后拖动吸附蜂窝；历史对象在首次移动前保留原坐标。中键 / 空格拖动平移，滚轮缩放。Ctrl+Z 撤销一笔或一次参数修改，Ctrl+Shift+Z 重做，Ctrl+D 复制，Delete 删除。输入框内使用文本编辑快捷键。窄窗口用“属性”展开 / 收起右侧面板。

“场景设置”可调整半径、平顶 / 尖顶朝向、蜂窝大小、空气墙高度 / 厚度 / 碰撞层、外部虚化、底色、羽化和自然围边开关。缩小战场后对象坐标保持原值，检查器标出越界。“灰盒预览”隐藏辅助线；光晕表达参数的大致效果，正式美术效果由 Godot 原着色器呈现。

蜂窝对象的范围由 hex_footprint 决定。需要原编辑器的矩形 / 圆形 / 多边形独立范围时，点“转为独立矩形范围”，再编辑范围属性。高级 JSON 可编辑组合树、围边簇等原有扩展字段。

水平部署与 Godot 斜视美术

全部41张战场采用己方在左、敌方在右，实际槽位与敌群的中心尽量在同一水平线上。左侧“双方部署水平对齐”会保留阵型与人数，避开实体障碍、深坑和陷阱，可用 Ctrl+Z 撤销。无敌方配置的历史模板只预留位置。

对象美术属性新增“Godot 美术摆放”和“离地倾角”：树、草、石头、蛛网默认离地60°（90°为竖直）；泥潭、深坑、落叶、干土和碎页岩贴片保持贴地。视觉倾角不移动物理碰撞或效果区，也不为战场美术增加描边。原生调试入口是 GodotBattlePreview/Start-BattlePreview.ps1，可比较45°、60°、75°；具体角色仍由战斗系统创建。

保存和交接

大地图和战场分别保存。大地图“保存布局”写入 Data/Maps/hex_layout.json；战场“保存战场”或 Ctrl+S 写入整个战场工作集 Data/Maps/hex_battles.json。已有文件会自动备份到各自的备份目录。切换不会自动保存；刷新或关闭前请保存两个编辑器的修改。

“导出工作集”输出可重新导入的 *.hex-battles.json，包含全部战场。也可导入原编辑器 frontier-map-editor 工作集中的战场；保存到当前工程时要求保留现有历史模板和来源版本。只提供部分战场的文件可用于查看和导出，直接覆盖工程会被阻止。

“导出接入配置”输出当前战场的 *.battlelevel.json，先修正检查器的布局错误。效果、怪物等业务 ID 可以保持待配置警告。结构包括 map、assets、art_bindings 和 catalogs。

开发接入约定

  • 保存格式为 frontier_hex_battles version 1，沿用旧战场对象结构。position 是世界 X/Z，height 为离地 Y，rotation 为平面角度，scale 为平面缩放。
  • hex_grid 保存单块宽度和原点；hex_cells 保存地面 / 控制层。hex_footprint 为相对对象中心的蜂窝中心数组，使用当前战场蜂窝方向和尺寸，跟随对象移动、旋转和缩放。
  • 接入导出会把每格效果转换为独立六边形多边形，并以 semantic_group 关联同一笔对象。区域之间的空白不会被包围盒填满。部署槽位按所属多边形分配，通路 / 效果的业务逻辑由战斗系统消费。
  • 红 / 橙控制格导出为不可破坏 / 可破坏碰撞对象，条件和事件保留。绿色标记和地面颜色保存在 hex_cells。控制层需与其他碰撞合并判定。
  • 怪物点位字段 monster_type、monster_size、grouped、count 独立。unassigned 表示待选择，不是第六类；同事负责具体怪兽外形。
  • visual.asset、broken_asset、active_asset、地面和背景素材引用保留。导入时解析现有返图前素材绑定，置换时修改引用 ID；接入导出中的 art_bindings 与对象当前视觉引用一致。assets 存储资源路径，不把图片嵌入灰盒页面。
  • HTTP API：GET /api/battles 返回工作集与 ETag；POST /api/battles 使用 If-Match，只允许同源回环访问。版本冲突返回 409，保留当前草稿，先导出再重新加载合并。
  • 蜂窝工作集为新增的编辑数据。正式 Godot 战场仍使用原 Data/Maps/<id>.json 与 Scenes/Maps3D/<id>.tscn；接入导出需由战斗系统或转换器导入并重建场景。保存灰盒本身不会执行战斗、伤害、奖励或改写玩家存档。
