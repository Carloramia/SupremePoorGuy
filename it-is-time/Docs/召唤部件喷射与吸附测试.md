# 召唤部件喷射与吸附测试

入口：`res://Scenes/Tests/SummonAssemblyLab.tscn`，打开后按 **F6**。也可双击工程根目录的 `运行召唤组装测试.cmd`（该启动器使用本机 E:/codex 中的 Godot 4.7.2）。原项目主入口仍为 `Scenes/Application/GameRoot.tscn`。

本次实现的是独立、可交互的 3D 演出实验台，使用真实已制作怪物；未替换正式游戏的召唤流程，也不修改仓库、战斗属性或原预制体。

## 当前抽卡观看节奏

**最新规则：正常 1× 播放全程固定 4.00 秒**，从起势开始到最后一只怪物回弹结束、站稳为止。1 / 2 / 5 / 12 / 20 / 30 只均使用同一总时长；没有在结尾补静止等待。标准与紧凑回拢两档也均为 4 秒，自动档只改变内部阶段的时间分配，不再缩短整段连抽时间。完成后的结果展示不计入这 4 秒；暂停、调速和主动跳过属于实验台观看控制。

组件 `total_duration` 与模板同名字段默认都是 `4.0`。先按原始阶段参数排好独立落地、吸附、空中组装及错峰回弹，再把整条时间线等比映射到 4 秒。保留先落地先吸附、怪物体型、散布、组装高度差及纸片始终平行镜头。下表及后文阶段秒数为**映射前的调度参数**，不再等于实际播放秒数；界面顶部显示换算后的实际停顿和吸附时间。`elapsed` / `duration` / `seek()` 使用实际演出秒数，内部部件时刻通过 `animation_time()` 比较。

按会反复观看的抽取动画处理，停顿与吸附时长可一起调整，不再锁死前轮的 0.5 秒 + 1 秒。

| 阶段 | 标准演出 | 连抽快节奏 |
| --- | ---: | ---: |
| 起势 | 0.12 秒 | 0.06 秒 |
| 发射窗口 | 0.34 秒 | 0.18 秒 |
| 基准飞行 | 0.82 秒 | 0.62 秒 |
| 每片落地停顿 | 0.16 秒 | 0.06 秒 |
| 每片加速吸附 | 0.48 秒 | 0.30 秒 |
| 基准整只下落 | 0.32 秒 | 0.24 秒 |
| 轻微回弹收束 | 0.20 秒 | 0.12 秒 |

阶段交叠，并非逐项串行相加。默认“自动”模式：第一次新抽标准，后续新抽快速；R 重播与数量预设保持当前节奏，不增加新抽计数，便于对比。同一结果的部件、体型与归属不会因为切换节奏重新生成。Enter 或“跳过”立即展示完整结果，完成只触发一次；结果始终保留供选择，不强迫立刻下一抽。手动切换标准/快速会在下一次播放生效。

## 已确定的演出逻辑

1. 本次结果先确定 N 个怪物及各自部件；演出本身不随机决定游戏结果。
2. 所有部件从同一个召唤阵交错高喷，初始落点在地面圆盘区域内随机采样，与所属怪物的最终位置无关；半径恢复为 **9.75**，用 `random^0.65` 径向采样，保留外圈落点，仅比均匀圆盘稍偏向中心。没有矩形边角，也没有归属色、编号、预先落点圈。圆盘是地面 XZ 平面上的圆，45 度透视镜头下自然呈现椭圆。纸片全程平行镜头，保留源素材的原始拼接角度，只改变位置，不自转、不翻转，也不在落地时躺平。
3. 按上表短暂停顿后，以 `p²` 缓入曲线从慢到快吸附。每片独立计时，不等待整批落完；后落地部件可能仍在飞行，早落地部件已经开始组装。
4. 部件吸向本次所属怪物的原始接点，但组装高度以 **2.4 米**为中心，上下错开 **1.2 米**；各只怪物分配不同高度，保持原旋转、比例和层级，所有部件到位后报告该怪物空中成形。汇聚位置也有少量左右、前后偏移，避免整齐排队。
5. 每只完成组装后 **0.02 秒**即开始整只下落。依各只组装高度变化，按自然接地时刻排序、保持错峰。标准档接地间隔上限为 **0.075 秒**，快速档为 **0.045 秒**；数量多时自适应压缩错峰间隔，避免最后几只长期悬停。需要错开接地时，把调整摊入下落，不增加空中站着等待的阶段。
6. 落地采用象征性的轻微回弹。标准档两下共 0.2 秒，快速档共 0.12 秒，快速档幅度也略减小。仅改变整只根节点的高度，不扭动肢体、不旋转纸片、不改变怪物体型。回弹结束后整批才允许报告完成。
7. 完成后保留五官、肢体等真实素材的组合结果，直到重播或清空。地面完整，不出现裂缝。

吸附开始时刻明确保存为每片的 `attract_at = land_at + landing_pause`，不使用“整批最后落地时间”或“某只怪物全部部件落地时间”。例如标准档 A 在 1.2 秒落地，则 1.36 秒开始吸附；B 在 1.6 秒落地，则 1.76 秒开始吸附。`part_attraction_started` 信号可单独接入每片开始移动时的表现。

轨迹是确定性演出轨迹；使用实际部件包围盒修正触地点，不启用散片物理碰撞。这样不会发生部件互撞、关节拉扯或 AI 提前移动造成的拼接失控。

立片基准绑定当前活动 Camera3D 的朝向，镜头角度变化时会同步更新部件朝向、底面对齐和组装接点；暂停或成形后仍保持绑定。无活动镜头时才使用 `card_pitch_degrees` 作为回退。

**当前时间参数**：标准档落地至拼好合计 **0.64 秒**；快速档为 **0.36 秒**。取消吸附时长的随机波动；喷射与落地时刻仍随机交错。曲线只有加速段，不在终点提前减速，到接点精确归位。界面提供独立滑块，可在同一播放档位下继续微调；切换档位会加载该档位参数。

## 当前默认模板

资源：`res://Resources/VFX/SummonAssembly_Default.tres`，可直接在 Godot 检查器中维护，并通过实验台根节点的 `default_template` 替换。

快速档为 `res://Resources/VFX/SummonAssembly_Quick.tres`，由实验台根节点的 `quick_template` 引用。

两档都沿用混合怪物 12 只、体型 3.2、种子 5169、喷射高度 9.0、播放速度 1 倍、散布半径 **9.75**、中心偏向指数 **0.65**。节奏切换只影响演出计时与轻量路径表现，不改变形体、部件归属或散布范围。

模板保存上表时长、加速指数 2.0、横向布局宽度 22、纵向布局深度 8、前后排最大间距 3.2。允许一定遮挡；体型、镜头和重叠选择逻辑不随密度改变。

## 素材与维护

使用 `Scenes/Creatures/Characters/` 中的灰狼、蛇兽、角兽、树桩兽、蜘蛛、人形六类已完成角色；实际网格、贴图和部件来自角色所引用的 `Scenes/Creatures/Bodyparts/` 资源及其保存的 GeneratedParts 姿态。每个 `PhysicalBodyPart3D` 是一个喷射单元，同一部件上的多块网格一起移动。

读取方式沿用工程现有头像预览的原则：实例化源角色但不加入场景树，准备部件几何，仅复制可见网格和材质，保存每个部件相对于角色的变换。原刚体、碰撞、AI、生成器和关节不会进入演出场景。`Generate_Bird.tscn` 当前没有可见部件，因此不加入默认素材列表；没有用占位图伪装成已完成素材。

维护贴图和接点时继续修改原 Character / Bodyparts 预制体；重新启动测试后读取最新资源。不要为了修改演出重新裁剪一套素材。

## 数量与体型

| 预设 | 数量 | 目标体型 |
| --- | ---: | ---: |
| 少量 | 2 | 保持当前值，默认 3.2 |
| 常规 | 5 | 保持当前值，默认 3.2 |
| 多量 | 12 | 保持当前值，默认 3.2 |
| 密集 | 20 | 保持当前值，默认 3.2 |

数量可手动设为 1–30，体型可设为 0.5–8.0，两者独立。数量变化不改变部件缩放，也不改变镜头距离；四个数量按钮只切换数量并保留当前体型。若要测试真实巨型或微型结果，再手动修改体型。勾选“按体型自动建议数量”时，采用临时测试公式 `round(5 × (3.2 / 体型)^1.15)` 并限制为 1–24；这只是实验台建议，不是正式游戏数量规则。

组件在固定区域内错位分行，数量越多间距越小，允许局部轮廓重叠。镜头固定为向下 45 度的透视镜头；同一怪物的显示大小仅受到自然透视深度影响，不按数量整体缩小。30 只是验证上限，不代表正式玩法数量上限。数量和体型同时设为极端大值时可能严重重叠，界面不会自动缩小素材来容纳。

## 实验台操作

### 动画节奏优化

以反复抽取的观看体验为依据，停顿、吸附、喷射和收束共同优化。当前数值见本页开头的两档对照表。

| 阶段 | 当前处理 | 阅读目的 |
| --- | --- | --- |
| 起势 | 短促的法阵收紧、提亮 | 给喷发一个清楚起点 |
| 喷涌 | 保留个体差异、压缩发射与飞行时间 | 高喷但不拖长，碎片交错出现 |
| 混落 | 9.75 半径圆盘，轻微中心偏向；每片短暂停顿 | 先看到混合部件，再理解组合归属 |
| 回拢 | `p²` 加速与浅弧线，两档分别使用 0.48 / 0.30 秒 | 从慢到快吸向接点，避免直线搬运感 |
| 拼合 | 接点精确归位，短暂四角压印提示 | 显示个体在这一刻成形；不放大或摇晃角色 |
| 落定 | 拼好后立即下落，轻微接地刻痕，短回弹 | 保留重量感和先后差，不让反馈拖尾 |
| 结束 | 最后站稳后 0.04 秒完成 | 减少流程恢复前的空等 |

起势脉冲、拼合压印、触地刻痕属于实验台的表现反馈层，用时间轴确定性采样，倒放、跳过和重播都不会堆积临时特效节点。纸片全程保持与镜头平行，不增加自转、镜头震动或体型缩放。角色的准确拼接与选中优先于提示效果；接点提示仅 0.14 秒，触地提示仅 0.18 秒。

模板新增 `anticipation_duration`、`flight_duration`、`launch_window`、`absorption_arc_height`。这些是本次动画测试参数，可在 `SummonAssembly_Default.tres` 中继续调整；不视为正式游戏的固定美术规则。

- `1 / 2 / 3 / 4`：四种预设并立刻播放。
- `R`：相同种子、相同档位重播；`N`：新抽，自动模式下后续新抽加速。
- 左栏节奏菜单：标准 / 连抽快速 / 自动；自动为默认。
- `空格`：暂停 / 继续；`Esc`：清空。
- 左栏：选择单一怪物或混合怪物，调整数量、体型、随机种子、喷射高度、散布、吸附耗时。
- 播放速度即时生效；其它参数在开始或重播时应用。
- 底部时间轴：拖动暂停并查看任意阶段，空格继续；支持往回检查。
- Enter 或跳过按钮：部件直接归位，单次批次完成信号只发一次；结果持续保留，不自动下一抽。
- 循环观察：结束 1.5 秒后按相同设置重播。
- 左栏可滚动，窗口较小时仍可访问底部控制。
- 成形后点击怪物显示选框与来源名称；重叠处优先选择前景单位，再次点击或 Tab 轮换到被遮挡的单位。Shift+Tab 反向轮换；鼠标不在重叠区域时 Tab 可遍历全部已成形单位。

选取用的是角色所有实际部件合并后投影到屏幕的包围矩形，不是逐像素透明检测。因此透明空白处也可能进入候选，但所有重叠候选均可轮换选中，不会因为被挡住而完全无法选择。

## 正式接入接口

可复用场景：`res://Scenes/VFX/SummonAssembly3D.tscn`。

```gdscript
# 用真实召唤结果生成请求。height 为演出显示尺度，不改变战斗数值。
var requests: Array[Dictionary] = [
    {"scene": "res://Scenes/Creatures/Characters/Generate_Wolf.tscn", "height": 3.2, "id": "wolf_001"},
    {"scene": "res://Scenes/Creatures/Characters/Generate_Snake.tscn", "height": 1.5, "id": "snake_001"},
]
$SummonAssembly3D.play_batch(requests)
```

支持请求内不同数量、不同种类和不同体型。`scene` 可以是资源路径或 PackedScene；读取到无可见部件的场景时返回 false，并提供 `load_error`。也支持单独的 Bodyparts 预制体做部件试验。

| 信号 | 时机与用途 |
| --- | --- |
| `batch_started(count, part_count)` | 成功准备本次演出，更新界面 |
| `part_landed(unit_index, source_path)` | 单个部件触地进入本档位短暂停顿，可接轻微落地音 |
| `creature_assembled(unit_index, visuals)` | 对应怪物全部接点到位，可接成形音 / 标记 |
| `creature_landed(unit_index, bounce_index)` | 整只接地，0 为首次落地，1 / 2 为两次回弹结束 |
| `creature_settled(unit_index, visuals)` | 两次回弹完成，怪物稳定站在地面 |
| `batch_finished(visual_roots)` | 整批完成，恢复后续流程；跳过不会重复发送 |

返回节点是演出用视觉节点，不是可战斗的 NPC。正式接入时由调用方在完成后以同一召唤结果创建实际战斗单位，并在同一帧清除对应演出视觉；不要让演出组件再次扣资源或重复生成仓库记录。本次仅实现、测试该视觉组件及实验台，不宣称已经接入主流程。

## 验证入口

`Tests/ValidateSummonAssembly.gd`：覆盖 2 / 5 / 12 / 20 / 30 只、全部六类素材、圆盘散布范围、独立部件归属、标准与快速档时长、自动连抽提速、重播不改变档位、持续加速、空中成形、错峰落地、两次回弹、最终底面对齐、接点、倒放、跳过幂等、清空与非法素材，以及固定体型、镜头与重叠轮换选择。

`Tests/CaptureSummonAssembly.gd`：在有图形的 Godot 运行，以相同 3.2 体型录制四档数量并保存实机截图。实际性能应在目标设备、正式场景和最终材质下测量；离线录制与 headless 验证不作为最终帧率保证。
