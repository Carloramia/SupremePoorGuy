# 新版六边形地图接入记录

## 当前状态

正式入口仍是 `Scenes/Application/GameRoot.tscn`。**开始新游戏默认使用 20261019 地图；继续旧档保持旧地图、位置和进度。** 没有对玩家已有存档做自动重置，也没有修改生物场景、物理控制器、攻击参数或召唤池。

运行时索引为 [Runtime/index.json](../../../Content/Maps/FrontierEditor_20261019/Runtime/index.json)。共接入 1 张大地图、41 张战场环境、39 处营地阵容配置，其中 31 处可用、8 处因物种尚未绑定而禁用。初始仍为空仓库，第一次进入地图自动打开待办事项；召唤小屋继续打开现有召唤界面。

## 本次改动

| 范围 | 实现与实际行为 |
|---|---|
| 版本与旧档 | GameRoot 的 `Use Hex Map For New Games` 默认开启；存档记录 `delivery_map_version`，地图快照记录 `map_version`。没有版本字段按 20261015 解释；校验旧快照时使用旧地图边界和地点表。两版共享既有会话/交易格式，但不会互相套用位置、迷雾和清剿状态 |
| 大地图 | 按源 q/r 创建 10,877 个六边形导航节点及六邻接，不创建百万级矩形节点；保留河流、山体、outside、桥和未破坏石障的通行规则 |
| 显示 | 保留图标宽度、anchor、分层、旋转和独立装饰；远景总览、近景原始高清块，48 个裁切版本按 even-odd 规则生成，保留 rect/offset 和透明孔洞。只缓存视野内分块，原件不重绘 |
| 战争迷雾 | 当前视野按山体外壳发出 256 条视线并截断，独立小坑不遮挡视野；探索记录存档。已知城镇在视野外保留暗色图标；缩远时名称仅悬停显示，避免总览被调试名称遮盖 |
| 石障 | 必须持有妖兽并抵达相邻可通行格。按源 walk_steps 和行走动画速度计时，成功后按三格实际地图距离/玩家旅行速度结算游戏时间；多 owner 格全部破坏才开放；永久山体和河流不会被一并开放 |
| 石障取消 | 打开阻止地图操作的菜单或退出会取消，不扣时间、不隐藏石头；取消的旧计时器不能提前完成后来启动的新动作；重复破坏不重复收费 |
| 战场 | 将全部 41 份编译多边形配置转换为现有 BattleHost 接口，保留独立障碍、空气墙、外围模糊和已配置的区域效果。40 个带有未绑定 effect_ref/condition_ref 的作用区禁用效果与接触监测，不套用示意值；可用 `trackmap on` 查看 environment_effect_disabled。内部装饰生成 50 份有厚度的共享纸片模型，装饰自身不增加碰撞，明确的障碍/作用区独立处理 |
| 阵容 | 按源 enemy 对象的 count 展开，沿用已注册 human/stump_beast/wolf/snake/horned_beast/spider。保留原阵容顺序；在新版地图先给占地大的敌人安排位置，再按原顺序生成角色，避免混合阵容留下零碎空位 |
| 原有游戏流程 | 保留友方左侧、敌方右侧且靠近中段的区域；朝向只取左右。复用原部署拖动、导航烘焙、真实 AI、战斗结算、回执、时间、返回来源点、设置、暂停和自由光标 |
| 事件 | 原有召唤等正式功能继续使用。交付的剧情事件保留 ID 和名称，执行图/条件/奖励未配置的入口显示待接入并禁用，不顺播全文发奖，不把浏览器演示当作真实事件执行器 |
| 导出 | Runtime 数据、贴图、模型和场景进入导出；Source/Data/Migration/Documentation/原始 Assets 留作资料并排除。源库原件使用 `.gdignore`，运行时仅导入实际采用的素材；SVG 的嵌套符号在运行副本中展平以兼容 Godot |

源数据和本次迁移的对应清单见 [资源对应与更新方案](地图交接包资源对应与更新方案_2026-10-19.md)。原版 `FrontierDelivery_20261015` 内容、旧阵容和物理资源保留，支持旧档继续使用。

## 开发入口与日志

- 新游戏地图开关：GameRoot Inspector 的 `Use Hex Map For New Games`。关闭只改变之后新建游戏的选择，不迁移已存档地图。
- `trackmap on` / `trackmap off`：追踪移动、交互、遭遇、破坏、保存与战斗返回。
- `mapstate`：查看当前地图版本、位置、10,877 节点导航状态、可见/探索格数量和当前交互。
- `mapstate layout_wolf_den_002`：查看可用灰狼营地的条件、可见性和遭遇配置；`mapstate layout_wolf_den_001` 可检查未绑定的流浪狗入口。
- `getlogs`：沿用原压缩归档功能。

内容生成工具为 `Tools/Integration/BuildHexMapRuntime.py` 和 `BakeHexMapPaperParts.gd`。前者从迁入的路径适配数据重建 Runtime 索引、地图、阵容、场景及高清裁切；后者复用 PaperVolumeMeshBuilder 烘焙 50 个模型。生成结果不作为第二个手工编辑源。外部地编仍使用交付包的正式 Data/Maps；内容更新需先同步迁移数据，再编译、导入、烘焙并重启游戏。此次没有移植浏览器地编 UI 或覆盖主工程 project.godot。

```powershell
python Tools/Integration/BuildHexMapRuntime.py
# 使用 Godot 编辑器导入新贴图之后：
Godot_v4.7.2-stable_win64_console.exe --headless --path . --script res://Tools/Integration/BakeHexMapPaperParts.gd --log-file D:/GameJamWorkspace/RuntimeChecks/hex-bake.log
```

## 验证与边界

- `ValidateHexWorldIntegration.gd`：坐标正反算、永久通行约束、共享石障、山体/坑的视野区别、版本隔离、存档读写、未绑定阵容阻断、41 场景/954 个装饰实例的实际加载。
- `ValidateHexWorldApplication.gd`：真实新游戏、待办、移动计时、保存失败回滚、部署六个真实角色、开始战斗、撤退结算、返回、退出菜单、读档；图形模式还保存出生点、全图和战场部署截图。
- `ValidateHexBattleDeployment.gd`：全部 31 处可用营地，在四种友军和完整敌群下检查边界、障碍、作用区和互相重叠约束。首次发现的 4 处混合阵容碎片化问题已修正并复核通过。
- `ValidateHexStoneActions.gd`：无妖兽拒绝、取消/重启计时、三格耗时、重复提交和读档恢复。
- `ValidateHexLegacySelection.gd`：旧 Frontier 存档在没有待结算战斗时仍选择旧后端；随后开始新游戏恢复 Inspector 配置的新版默认值。
- 旧版 `ValidateDeliveryApplication.gd`、`ValidateDeliverySaveAndEffects.gd` 回归通过。依赖旧坐标的测试显式选择旧版；新默认流程由独立测试覆盖。
