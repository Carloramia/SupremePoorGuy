# 程序驱动动画场景与音效需求（2026-10-19）

## 口径与结论

本清单以正式 `GameRoot` 及其继承的 `GameUIController`、召唤演出、可部署角色的程序驱动运动/攻击为主；同时单列已有脚本但未进入当前随机召唤池的 Bird、Rat。统计单位是**可独立决定音效触发时机的演出场景**，不是动画文件数或生物场景文件数。物理自然摆动、鼠标连续移动、调试可视化不逐帧配音。依据为代码和配置静态核查，未做逐场景试听。

共整理 **30 个候选场景**：召唤 6、移动与姿态 5、战斗与伤害 12、界面 7。其中现有战斗系统只有 `attack`、`bite`、`charge`、`stomp`、`bow`、`hit`、`break` **7 个已配置的通用事件**，每类 2 个原型 WAV；“已接入”表示有调用且资源可播，不表示最终声音设计完成。现有 `blade_*`、`hit_crisp_*` WAV 不在 [CombatAudio.tres](../../../Resources/Audio/CombatAudio.tres) 的 cue 列表内，不能按已接入计算。详见 [现有音效说明](README.md) 与 [播放服务](../../../Scripts/Audio/CombatAudio3D.gd)。

优先级：**P0** 为影响动作反馈、命中判断或主要演出的首批交付；**P1** 为强化辨识和节奏；**P2** 为界面/环境润色。表中事件 ID 是建议接口名，标“已有”的沿用现有 ID。

## 首批制作与接入方案

1. **先保住现有事件合同。** 继续使用 7 个旧 ID；用录制/设计音替换原型 WAV 时先试听同屏多角色与实际距离。原型资源仅能验证时机。建议首批新增 8 个独立事件：`summon_part_emerge`、`summon_part_land`、`summon_part_attract`、`summon_part_lock`、`summon_creature_complete`、`summon_reveal`、`footstep`、`arrow_impact`。
2. **素材交付建议。** 每个离散事件至少 3 个可随机变体；需分轻/重的落地、脚步、命中各做 2 组。召唤吸附/蛇滑行/飞行掠风是可循环素材，必须提供无缝循环点和 100–200 ms 淡入淡出。离散声用单声道 48 kHz、24 bit WAV，UI 可用立体声；响度以混战场景试听定稿，不把表中的优先级当音量等级。
3. **位置与去重。** 世界声放在接触点、部件或角色所在的 `World3D`；召唤演出是独立 SubViewport/World3D，需验证听者位置与暂停/跳过清理。脚步按“角色+脚”冷却，召唤部件按“单只生物”限流，完成音每只一次、整场揭晓一次。攻击前奏、真实命中、Broken 可叠，但同一撞击要有总量限制。
4. **动态参数。** `footstep` 读取脚部质量、接地速度、地面材质；`hit` 读取实际伤害与目标材质；滑行/掠风循环读取速度。所有读值只影响音色/响度，不改变攻击判定或物理动作。
5. **验收。** 对每项检查“触发一次、取消不残留、暂停/恢复正确、远近衰减、同屏多只不轰鸣”。重点回归召唤的跳过/离开、部件延迟落地、冲锋未命中、箭矢穿行但未命中、Broken 连带、Bird/ Rat 测试场景。沿用 [现有战斗音频测试](../../../Tests/ValidateCombatAudio.gd) 检查旧 7 类；新增事件需要补相应集成检查并做真人试听。

## 边界

Bird、Rat 在当前 [随机召唤池](../../../Scripts/Application/CreatureFactory.gd)之外，其 P1 音效可在正式开放角色前完成。自然刚体碰撞、镜头拖动、地形瞄准弧线与持续 Shader 变化暂不单列音效；只有玩家可感知的状态改变、明确接触或需要持续辨识的运动才加入事件表。
