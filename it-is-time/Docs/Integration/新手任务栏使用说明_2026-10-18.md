## 运行行为

首次进入大地图时启用新手任务。点击已有“待办事项”按钮打开列表，保留全部任务；未解锁任务注明前置条件，完成任务显示勾选并永久保留。全部完成时显示“新手指引已完成”。

从主菜单选择“开始游戏”创建新存档后，在大地图加载就绪时自动打开一次待办事项。关闭后不会自行重复弹出；继续游戏、战斗返回和重新载入存档不会自动打开，仍可通过待办事项按钮查看。再次开始新游戏会为该新游戏重新打开一次。此行为适用于两个地图后端；加载失败时不提前弹出，也不覆盖加载期间打开的其他窗口。

待办仅在大地图可用，加载、部署、战斗、结算、城镇及主菜单阶段禁用入口。探索与战斗任务的“前往”关闭待办返回地图，召唤任务进入召唤页，准备出战进入出战队伍页。锁定与已完成任务不执行跳转。

本次不包含独立 2.5D 开场场景、剧情事件或黑幕点击引导。开场场景自行负责进入大地图前的流程，无需另行调用任务启用接口。

## 修改任务配置

配置入口为 [NewPlayerTasks.gd](../../Scripts/Application/NewPlayerTasks.gd) 的 `DEFINITIONS` 数组。当前四项任务的魔力、符文和奇物奖励全部为零或空列表，保留奖励能力。

```gdscript
{
    "id":"explore_frontier",
    "title":"探索边境",
    "description":"实际抵达任意一个可交互地点。",
    "prerequisites":[],
    "condition":{"type":"location_arrived", "count":1},
    "action":"world",
    "reward":{"magic":0, "runes":[], "relics":[]}
}
```

| 字段 | 规则 |
| --- | --- |
| id | 唯一且稳定的任务 ID。已发布任务不要改 ID，否则会被视为另一条任务 |
| title／description | 列表名称与操作说明 |
| prerequisites | 前置任务 ID 数组，全部满足才解锁；空数组表示无前置 |
| condition.type | `location_arrived`、`summon_settled`、`party_members` 或 `battle_victories` |
| condition.count | 正整数阈值，缺省为 1 |
| action | `world`、`summon` 或 `party` |
| reward.magic | 非负整数魔力，缺省为 0 |
| reward.runes | 要解锁的符文 ID 数组，缺省为空 |
| reward.relics | 要解锁的奇物 ID 数组，缺省为空 |

例如奖励可以配置为 `{"magic":20,"runes":["iron"],"relics":["bone-die"]}`。此示例未用于首批任务。符文与奇物名称通过现有 RuneRules 查询；解锁参考内容不会替代 GameSession 对实际战斗能力的支持检查。

保持当前新游戏全部开放的策略。缺省 `known_runes`／`known_relics` 仍代表全部开放；奖励已拥有的内容时不重复添加、不折算其他补偿。

重复任务 ID、不存在的前置任务、循环依赖、未知条件或跳转类型，以及负数、非整数或未知内容的奖励会阻止存档提交，并给出错误。新增条件类型时，在同一规则文件增加校验、事实采集与判定，再补测试。

## 首批任务与完成依据

| 任务 | 前置 | 实际判定 |
| --- | --- | --- |
| 探索边境 | 无 | 真实地图抵达记录；不是创建地图存档或仅发现图标 |
| 完成召唤 | 无 | 成功产生至少一只，并安置完同批结果；仅提交召唤或全部失败不算 |
| 准备出战 | 完成召唤 | 曾有至少一只出战成员；满足前置后可追认早先行为 |
| 赢得一次战斗 | 准备出战 | 胜利结算与任务进度成功保存 |

前置关系与数组顺序无关。可靠事实会保存，因此先编队、后安置，或前置任务解锁前已获胜，都可以在满足依赖后自动补判。完成后清空队伍、失败、撤退或改变当前状态不会撤销完成。

## 存档与旧档

任务使用统一 GameSession 存档中的 `new_player_tasks` 字段：保存启用状态、可靠事实、完成任务及当时的奖励回执。完成与对应奖励在原业务存档事务内一起提交，成功后再发完成通知；失败回滚，重试不重复扣费或发奖。

旧档无需事先添加字段。进入地图启用时，从下列可靠记录补判：

- 交付地图的 `visited` 地点，或旧地图 `location_runtime_states` 中大于零的访问次数。
- 成功报告且无待安置结果，或仍存在的同批生成实例及其安置状态。
- 当前真实出战成员。
- 已保存且结果为 victory 的战斗回执。

无充分记录的目标保留未完成。首次追认补发当前任务配置奖励，之后按任务 ID 去重。修改已完成任务的奖励不会再次补发；其展示保留当时的奖励回执。新游戏重置本存档的任务和奖励记录，继续游戏保留现有记录。

## 接入点

- GameSession：统一存档时执行规则；`enable_new_player_tasks()` 用于地图启用与旧档补判。
- GameRoot：两个地图后端的首次进入；旧地图实际交互开始时记录抵达；连接完成反馈与列表刷新。
- DeliveryMapBridge：复用已有已访问地点记录，并补充合法营地抵达记录。
- GameUIController：阶段门禁、任务 ID 路由、简短完成提示。
- TasksView：复用现有纸页、任务行和滚动容器。带任务 ID 的数据保留锁定与完成条目；不带 ID 的原型数据继续使用旧待办展示语义。
