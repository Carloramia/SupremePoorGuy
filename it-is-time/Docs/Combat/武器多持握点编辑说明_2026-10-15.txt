武器多持握点编辑

功能由 SampleWeapon3D 和已有 Weapon Workshop 编辑器插件共同提供，所有继承 _SampleWeapon 的武器都可使用。
默认数量为 0，保留现有 Attachment 参数，不改变旧武器的持握姿态。

一、创建与调整
1. 打开具体武器场景，选中根节点。在 Inspector 顶部找到“武器持握点”。
2. 将“数量”设为需要的数量，系统创建 GripPoints/GripPoint_01、GripPoint_02 等 Marker3D。
   第一个点使用当前 Attachment Local Position 和 Item Rotation；新增点先放在同一位置，随后可分别调整。
3. 在场景树选中一个 GripPoint Marker，移动它至希望持握的位置。
4. 调整 Marker 的 Transform / Rotation Degrees / Z，即该点装备后武器的旋转角度。
   Marker 的 X/Y 旋转应保持 0，Scale 保持 (1,1,1)。读取时使用相对于武器根节点的坐标。
5. 在该 Marker 的 Inspector 点击“读取此 Marker 到持握点”，仅更新对应的点。
   也可以回到武器根节点，点击“读取所有 Marker 到持握参数”，一次保存全部点位。
6. 在根节点选择“当前持握点”，然后保存武器场景。

“生成/同步持握点 Marker”可补回被手动删除的 Marker。
移动或旋转 Marker 不会自动提交；必须点击读取按钮，装备才会使用新的数据。
读取当前点会同时更新根节点 Attachment Local Position、Item Rotation 和 Has Attachment Point。
读取其他点只保存该点的数据，保持当前点不变。
启用多持握点后，根节点 Attachment Local Position 与 Item Rotation 是当前点的镜像值；直接改这两个字段不会改持握点数据，下一次装备会重新应用当前点。
Marker 是编辑辅助节点，不会增加游戏中的物理碰撞、质量或渲染模型。
修改具体武器的持握数据不会修改它引用的图片、模型、碰撞形状、厚度或其他武器资产。

每个持握点指定 Arm：
1. 选中 GripPoints/GripPoint_01 等 Marker，在 Inspector 找到“吸附 Arm（角色内名称 / 路径）”。
2. 填写 Arm_R、Arm_L 等部位名称，或相对于装备角色根节点的完整路径，例如 GeneratedParts/Arm_L。
   先按相对路径查找；单独填写名称且角色根节点没有该部位时，在其内部查找唯一同名的物理部位。
3. 点击“应用吸附 Arm 到持握点”，或在输入框内按回车，然后保存武器场景。
   该设置立即保存到此持握点的数据中，不需要再点击“读取 Marker”；支持撤销/重做。
4. 装备或运行时切换当前持握点时，会将这个点对齐到对应 Arm 的 ItemSocket3D，并将武器的物理形状与质量绑定到该 Arm。
   从一个 Arm 切换到另一个时，会取消原 Arm 的攻击、还原原质量/碰撞形状/视觉状态，再绑定新 Arm。
   当前仍按根节点“当前持握点”选择一个生效点，各个 Marker 保存独立的 Arm 配置。

留空时沿用武器 Preferred Holder Name 和物品栏默认 Arm。旧武器不需要补填。
指定的目标必须是本角色内、带有 Arm 标签且未断裂的 PhysicalBodyPart3D；不支持绝对路径、角色外部节点或属性路径。
指定目标无效时不会自动改绑其他 Arm；初始装备会拒绝该武器，已装备武器切换持握点时返回 false 并保留原绑定。
同名部位不唯一时请填写完整的角色内路径。独立编辑武器时可以先填写名称，运行时按实际装备角色解析；重新生成角色后会重新解析新部位。
若需要让所选 Arm 参与攻击，该 Arm 还需配置 Arm Swing Bindings，并包含在角色 LimbSwingController 的相应控制组中。
持握点数量减少时仍会保留停用点的 Arm 设置；数量设为 0 时使用旧 Attachment 和 Preferred Holder Name 设置。
trackgrip on / gripstates 日志中的 requested_arm 显示当前持握点指定的 Arm，holder 显示实际绑定部位；requested_arm 为空表示沿用原设置。

二、保存与撤销
创建、读取、切换和数量调整都接入 Godot 的撤销/重做。
每个 Marker 及对应持握数据保存在武器 tscn 中，重新打开或实例化时仍然保留。
数量减少时停用并隐藏多出的 Marker，保留它们的数据，以兼容继承场景并避免删除继承节点；恢复数量后可继续使用。
当前选择超出范围时自动回到有效范围；撤销可恢复此前的数量、选择和 Marker 姿态。
数量设为 0 后，继续使用最后保留的 Attachment 参数。
请优先编辑具体武器场景；修改基类场景的配置时，未覆盖这些配置的子场景会按 Godot 的场景继承规则继承它。

三、装备与运行时
这些是可选的持握点，每次装备使用一个当前点。
玩家与 NPC 共用同一套装备流程，初始化装备会读取保存的当前持握点。
编辑场景后重新运行测试。脚本在运行时切换点位时，使用：

weapon.select_grip_point(1)

代码索引从 0 开始，因此上述代码选择 Inspector 显示的第 2 个点。
返回 true 表示成功，非法索引返回 false。
切换已装备武器的点位时，先结束旧攻击并恢复关节，再重新对齐手部 ItemSocket3D、合并碰撞形状及计算质量中心。
直接修改 active_grip_point 只会影响下一次装备；实时切换应调用 select_grip_point。
武器的 Attack Forward Local 仍表示武器局部的攻击端朝向；如果新的握点让该方向发生明显变化，请按攻击需要另行调整该向量。

四、按钮未显示时
确认 项目设置 / 插件 / Weapon Workshop 已启用；新增插件代码后可重新启用该插件或重启编辑器。
这里的按钮通过 EditorInspectorPlugin 提供，不要求把武器及其所有子类改为 @tool，也不向场景序列化 Callable。

代码入口
Scripts/Items/SampleWeapon3D.gd：多持握点数据与运行时选择。
addons/weapon_workshop/grip_edit.gd：Marker 生成、读取、持久化与撤销快照。
addons/weapon_workshop/grip_inspector.gd：武器根节点与单个 Marker 的 Inspector 控件。
Tests/ValidateWeaponGripPoints3D.gd：编辑数据、保存重载、运行时重新装备与兼容性验证。
